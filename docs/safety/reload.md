# Reload: making sshd use an installed configuration (`pkg/host/reload`)

> **Unit:** refactor plan Phase 2, `next/p2-reload` (brief 2.3 steps 3, 4 and 7; plan §2 `p2-reload` row: mechanics only, the ordering rule is `p3-engine`'s). V-numbers: V7 (restart instead of reload, no `sshd -t` before activation), V12 (`ssh.socket` not handled), and the reporting half of V24 (v0.3.x's `ssh.socket.d/listen.conf` left behind) ([side-effects.md](../refactor/phase0/side-effects.md)). Brief corrections it implements: [phase0-findings.md §12](../refactor/phase0-findings.md#12-proposed-adjustments-to-the-brief), rows 23 and 24 (commits 3b9c17a and 50f957b say "rows 21 and 22", the draft's numbering).
> **Status:** built and tested on macOS against the recording fake (`hostfake`) only, with `systemctl`, `rc-service` and `ss` answers written in the format of their sources (§3), not captured from a host. Nothing has run on Linux; §4 lists what is "written, not run (gate 5)", among it that SSH sessions survive a restart of `ssh.socket`.

Once `00-hardn.conf` (or hardn's block) is validated and installed, the running sshd still uses what it read before. `reload.PlanFor(in)` says, from detect's SSH facts and the keywords the change touched, which commands make it reread the files, in which order, which listeners must then be bound, and which listeners the caller must keep configured until the change is confirmed. `reload.Execute(ctx, sys, plan, opts)` runs the plan over `host.System`: it checks with `ss` that a port the change adds is free, runs the steps, checks that each unit is still up, then checks the bound listeners with `ss`. `ReadSocketDropIns` reports `ssh.socket`'s pre-existing drop-ins, and `OpenRCFlavour` names the sshd binary Alpine's init script runs.

## 1. Why

origin/main writes the sshd files and runs `systemctl restart ssh` or `rc-service sshd restart`, with no `sshd -t` and no socket handling (V7, V12). On Ubuntu 24.04 and 26.04 sshd is started by `ssh.socket`: a reload there cannot move the port, and a port change reaches the socket only through `daemon-reload` and a restart of `ssh.socket`, while a firewall that already allows only the new port locks the user out (V12 with V9). v0.3.2's `listen.conf` overrides the socket's generator and was never followed by `daemon-reload` (V12, V24). The `sshd` unit alias that a guess would call is missing on a fresh Ubuntu 24.04 (findings §12 row 24). Brief §3 principle 1: never lock the user out.

## 2. Guarantees

### Planning (`PlanFor`, pure)

1. **The steps follow the SSH mode detect established**, and an Unknown mode is refused (`ErrModeUnknown`, wrapping `SSH.Err`, for example detect's `ErrConflict`): hardn does not guess which unit listens ([detect.md](detect.md) §2.7, §6).

   | Mode (platforms) | A listener keyword changed (`Port`, `ListenAddress`, `AddressFamily`) | Only other keywords changed |
   |---|---|---|
   | `SSHSocket` (Ubuntu 24.04, 26.04) | the added ports free (`ss -Htln`, §2.8a); `systemctl daemon-reload`; check `systemctl show -p Listen ssh.socket`; if `ssh.socket` is active, `systemctl restart ssh.socket`; it is still active; then verify | if `ssh.service` is active, `systemctl reload ssh.service` |
   | `SSHService` (Debian 13, 12; Proxmox VE 9) | the added ports free; if `ssh.service` is active, `systemctl reload ssh.service`; it is still active; then verify | the same, without the `ss` reads |
   | `SSHOpenRC` (Alpine 3.24, 3.23) | the added ports free; if OpenRC has started sshd, `rc-service sshd reload`; it still is; then verify | the same, without the `ss` reads |

   Keywords are compared case-insensitively; no keyword means an empty plan (the engine's second, idempotent plan reloads nothing). A `Rollback` plan (§2.6a) is the same, except that a unit that is not up is started: `ssh.socket` is restarted whatever its state, `ssh.service` started (`systemctl start ssh.service`), OpenRC's sshd started (`rc-service sshd start`); on a socket host, `ssh.service` for other keywords is left to the socket. Tested per platform, with detect's facts for each stock install.
2. **Never the `sshd` unit on systemd.** Only `ssh.service` and `ssh.socket` are named, as full unit names (`ssh` and `ssh.service` are the same unit; the full name leaves no doubt). Tested: no argument of any systemd plan starts with `sshd`. On OpenRC the service is `sshd`, its real name.
3. **Reload, not restart, for sshd itself.** `systemctl reload ssh.service` runs the unit's `ExecReload` (`sshd -t`, then `kill -HUP`), and `rc-service sshd reload` runs the init script's `checkconfig` (`sshd -t`) before `HUP`: a configuration sshd rejects fails the reload and leaves the old daemon running (§3). The one restart is `ssh.socket`'s, which the socket needs to bind a new port.
4. **A listener change on a socket host must reach the socket.** It is refused before anything runs when the socket's listeners would not come from `sshd_config`: `Generator` not Yes (masked, absent as on a Debian host opted into the socket, or Unknown: `ErrNoGenerator`), or a pre-existing drop-in with a `ListenStream` line, such as v0.3.x's `listen.conf` (`ErrSocketDropIn`; its listeners replace the generator's, §3), or one named `addresses.conf`, the generator's name, masked or not (it replaces or masks the generator's, §3). The caller must pass `ReadSocketDropIns`'s answer (`fs.ErrInvalid` otherwise). After `daemon-reload`, the socket's configured listeners are read back, and **the socket is not restarted unless they cover every listener the files name** (`*ListenerError`, `ErrSocketConfig`), so a generator or a drop-in hardn does not model cannot rebind the socket onto the wrong port. There a socket `[::]` counts as dual-stack, systemd's default, and `0.0.0.0` as IPv4 only, so an IPv4-only socket does not pass for sshd's `[::]` (tested). `BindIPv6Only=ipv6-only` makes a `[::]` IPv6 only, and `systemctl show -p Listen` does not print it (§3): only the `ss` check after the restart sees that.
5. **The old listeners stay until the change is confirmed (requirement, returned as data).** For a listener change, `Change.Before` is `sshd.ReadEffective`'s `Listeners` before it, and a `Before` that is not `Known` is refused (`ErrListenersUnknown`, tested), so the hold is never built from an incomplete set; `Change.After` is what the installed files configure (`Listeners.SSHD` of `sshd.Evaluate` over the validated candidate). A forward change must keep every listener of `Before.All` in `After`, or the plan is refused with a `*HoldError` (`ErrDropsListener`) naming the missing ones; `Plan.Hold` is `Before.All`, `Plan.Adds` the listeners of `After` that `Before` does not cover (§2.8a), and `HoldPorts(Plan.Hold, want)` the Port lines to write: the old ones beside the new. Port and ListenAddress accumulate, so sshd, and the generator from it, configure both (§3). After confirmation from a new connection (`p2-revert`), the clean-up change is planned with `Confirmed`, which may only drop listeners: one that adds a listener `Before` does not cover is refused (`ErrAddsListener`, tested), so `Confirmed` cannot skip the hold of a first port change. This holds on every mode, not only the socket's that the plan row names: a reload on `ssh.service` or OpenRC rebinds too (§3, [I]), so dropping the old port there is the same lockout window. Coverage: the same port, and the same address or an unspecified one of the same family (sshd binds `::` IPv6-only, §3), so `AddressFamily inet` dropping `[::]:22` is refused, and widening `ListenAddress 192.0.2.10` to `0.0.0.0` is not.
6. **Alpine: no change that may switch the sshd binary.** `UsePAM`, `KerberosAuthentication` and `GSSAPIAuthentication` decide whether the init script runs `sshd`, `sshd.pam` or `sshd.krb5`, and its reload signals the binary the new files call for (`start-stop-daemon --exec`), which may not be the one running (§3, [I]). Such a change is refused (`ErrFlavour`); it needs a restart, which is a later unit's call.
6a. **A rollback starts what is down.** `Change.Rollback` plans the reload of restored files (`p2-revert`): it may drop listeners, `Before` is not used (the unit it restores may be down, so `ReadEffective` would not be `Known`), `Plan.Hold` and `Plan.Adds` are empty, and each gated step carries `Step.Start`, run instead when the unit is not up (§2.1, §2.9). That is what brings back an `ssh.socket` a failed restart left failed: a forward plan would skip it as not up and leave nothing listening (tested). Set it only when the unit was up before the change it undoes (that change's gated step ran), or the rollback starts a daemon that was stopped on purpose. `Confirmed` with `Rollback` is refused (`fs.ErrInvalid`).
7. **Pre-existing socket drop-ins are reported.** `ReadSocketDropIns` lists every `*.conf` in `ssh.socket.d` under each directory of systemd's unit load path that holds hand-made, runtime or packaged configuration: `/etc/systemd/system.control`, `/run/systemd/system.control`, `/run/systemd/transient`, `/etc/systemd/system`, `/run/systemd/system`, `/usr/local/lib/systemd/system`, `/usr/lib/systemd/system` (§3). The generator directories are not read: the generator's own `addresses.conf` is there. Each file's `ListenStream` values in its `[Socket]` section are given in order (`""` is the empty assignment that resets the list), read with systemd's comment and continuation rules; a symlink to `/dev/null` is `Masked`. Nothing is edited (migrating `listen.conf` is `p2-sshd-migrate`'s). A missing directory holds none; any other error fails the read (`Read` false), since an unread drop-in may move the listeners. `Plan.DropIns` carries them, refused plans included, for the caller to report.

### Executing (`Execute`)

8. **Steps run in order and stop at the first failure;** the `Report` holds every step up to the failed one with its `host.Result`. A command's error is returned wrapped with its argv (`*host.ExitError` for a non-zero exit, with the output tail: `sshd -t`'s complaint for a failed reload).

8a. **A port the change adds must be free.** When `Plan.Adds` is not empty, `Execute` reads `ss -Htln` before any step and refuses (`ErrInUse`, nothing run) when a socket that is not one of `Hold`'s (those are the running sshd's or `ssh.socket`'s) is bound on a port of `Adds` at an equal or unspecified address on either side, whatever the family, or when `ss` printed a LISTEN line hardn cannot read. On a socket host a port `systemctl restart ssh.socket` cannot bind fails the whole start and closes every port of the socket, port 22 included (§3); on `ssh.service` and OpenRC sshd skips the port, keeps the others, and the `ss` check after the reload would take the other program's socket for sshd's (§3). The rule is conservative (fail closed): `0.0.0.0` and a v6-only `[::]` on one port can coexist, and are still refused. `ss` missing refuses on a socket host (the port cannot be shown free); elsewhere the change goes ahead and the check after the steps cannot read `ss` either (`ReasonNoSS`). Tested per mode, with sshd's own socket not refused when `ListenAddress 192.0.2.10` widens to `0.0.0.0`.
9. **"Is it up" is asked at the moment, not taken from detect, before and after the step.** A gated step first runs `systemctl is-active <unit>` (or, on OpenRC, looks for `/run/openrc/started/sshd`, as detect does). Not up: the step does not run, and `StepReport.NotUp` says why; sshd reads the files on disk when it next starts (on Ubuntu, `ssh.service` is inactive until the first connection, which then starts sshd from those files). The check comes after the files are installed, so a unit that starts in between reads the new files. A `Rollback`'s step runs `Step.Start` instead (`StepReport.Started`): a not-up unit is started, `ssh.socket` with `systemctl restart`, which starts a unit that is not running (§3). Once the step ran, the unit is asked again. Down then is `ErrUnitDown`, wrapping the step's own error when it failed: on `ssh.service` (Debian, Proxmox VE) and OpenRC sshd is the only listener, and a restart that leaves `ssh.socket` down is the failure itself (tested per mode). The one exception is `ssh.service` on a socket host (`Step.Activated`): `ssh.socket` keeps listening and starts it at the next connection, so a reload that fails while it stops, or a stop just after, is `NotUp`, not an error (tested). Still up after a failed step: the step's error stands (a reload `sshd -t` rejected, the old daemon running). A state that is neither (`activating`, …), before or after, is `ErrUnitState`: no guess. The second check sees a unit that is down by then; a re-executed sshd that dies later, or OpenRC's sshd crashing (its started link stays **[I]**), is not seen: proof is the confirmation from a new connection.
10. **The real listener is verified with the bound sockets.** `sshd -T` and `systemctl show -p Listen` are configuration ([sshd-effective.md](sshd-effective.md) §2.5): after `daemon-reload` both name the new port before anything binds it. So once the steps are done, `ss -Htln` must show a LISTEN socket covering every listener of `Plan.Verify` (an `ss` `*` is dual-stack and covers both families). A reload signals sshd and returns before sshd has rebound, so the check polls: `Options.Attempts` (default 10) reads, `Options.Interval` (500 ms) apart; then `*ListenerError` with `ErrNotBound` and the missing listeners. `ss` missing (`host.ErrNotFound`: no iproute2) leaves the change `Unverified`, not failed; `ss` failing is an error. `Verified` says only that something is bound on those addresses and ports, not that it is sshd (§2.8a refuses the case where another program already was): proof is the confirmation from a new connection (brief 2.4, `p2-revert`). When not `Verified`, `Report.Reason` gives a stable code with `Unverified`'s words: `ReasonNotUp` (comes first, so a down unit is not reported as "no listener changed"; tested), `ReasonNoListenerChange`, `ReasonNoSS`. There is no `ss` check for a change that moves no listener: right after `systemctl reload` or `rc-service sshd reload` the old daemon may still hold its sockets (`kill -HUP` returns before sshd handles the signal **[I]**, §3), so a read then proves nothing.
11. **Context.** A done `ctx` is refused before anything runs; a rollback after Ctrl-C must pass `context.WithoutCancel(ctx)` (tested), as every `host.System` method requires ([system.md](system.md) §2.5). Ctrl-C during the listener check returns `ctx`'s error with the steps that ran in the `Report` (tested), for the caller's rollback. Every command reaches the run log through `host.System`.
12. **Through `host.System` only.** Depguard rule `reload-through-host` denies `os`, `io/ioutil`, `golang.org/x/sys`, `syscall`, `net` (except `net/netip`) and `plugin` to the package's non-test files; `host-stdlib` keeps it to the standard library and `pkg/host/...`.

### Alpine's binary (`OpenRCFlavour`)

13. It mirrors the init script's `update_command`: `/usr/sbin/sshd.krb5` when executable and its own `sshd.krb5 -f /etc/ssh/sshd_config -G` prints `KerberosAuthentication yes` or `GSSAPIAuthentication yes` (any case, whole line), else `/usr/sbin/sshd.pam` when executable with `UsePAM yes`, else `/usr/sbin/sshd`. For `sshd.Validate`'s and `ReadEffective`'s `Binary` ([sshd-validate.md](sshd-validate.md) §6). Where the script ignores a failing `-G`, this returns its error. An `/etc/conf.d/sshd` whose non-comment lines name `SSHD_BINARY`, `SSHD_CONFIG`, `SSHD_CONFDIR`, `cfgfile`, `command_args` or the deprecated `SSHD_OPTS` is refused (`ErrConfd`): the script would run another binary, read another file than hardn models, or pass sshd arguments (`-f`, `-o`) to both `"$command" -t` and the daemon (§3). The stock file has none (all its lines are comments).

## 4. Written, not run (gate 5)

Nothing here has run on Linux; no test starts `systemctl`, `rc-service`, `ss` or `sshd`. On the Ubuntu 26.04, Debian 13 and Alpine 3.24 VMs (`next/p2-vmtest`), on an Ubuntu 24.04 host, and by hand on Proxmox VE 9:

- **existing SSH sessions survive `systemctl restart ssh.socket`** on Ubuntu 24.04 and 26.04, both before the first connection (`ssh.service` inactive) and after it (the session running the change keeps working; §3, `KillMode=process` **[I]**), and survive `systemctl reload ssh.service` and `rc-service sshd reload`;
- the brief's 2230 scenario on Ubuntu 26.04: `Port 22` and `Port 2230` written, `daemon-reload`, `systemctl show -p Listen ssh.socket` naming both, `systemctl restart ssh.socket`, `ss -Htln` showing both, then the confirmed clean-up dropping 22; and what `ss` shows between `daemon-reload` and the restart (2230 not bound is expected, §3);
- a reload on Debian 13 and Alpine moving the port (§3 **[I]**), and how long sshd takes to rebind after `HUP` against the 10 × 500 ms poll;

- **new connections accepted after a reload** on each mode: `systemctl reload ssh.service` on Ubuntu (sshd closes the listening descriptors systemd passed it and re-executes, §3), on Debian 13 and Proxmox VE 9, and `rc-service sshd reload` on Alpine; and what `systemctl is-active` prints right after the reload (`active` or `reloading`, both up; `activating` would fail the plan);

- `ss -Htln`'s output on each platform (§3 **[unverified]**), whether `ss` is installed on each stock image, and a dual-stack `*` line for `ssh.socket` on Ubuntu;

## 6. Not in this unit; inputs to later units

- **`p3-engine`:** the order. `PlanFor` is pure and its inputs exist before anything changes (detect's SSH, `ReadEffective`'s `Listeners`, `Evaluate` over the validated candidate, `ReadSocketDropIns`), so it runs at plan time, before the firewall step, and its refusals (`ErrSocketDropIn` for v0.3.x's `listen.conf`, R8; `ErrNoGenerator`, `ErrFlavour`, `*HoldError`, `ErrModeUnknown`) show in a dry run. Brief 2.3 then applies: the firewall allows the new port first (`p2-ufw`), then write and validate (`sshd.Validate`, with `OpenRCFlavour`'s binary on Alpine), install, and only then `Execute`, then `sshd.ReadEffective` to compare the values it wanted. For a port change, write `HoldPorts(Plan.Hold, want)` for the confirm window; plan `Confirmed` only after `p2-revert`'s confirmation. Treat `Unverified` (`Reason`) and `NotUp` as "not proven": the confirmation from a new connection is the proof. Any error from `Execute` (`ErrInUse` before any step; `ErrUnitDown`; a `*ListenerError`) means stop and roll back while the session is open. Open: on Ubuntu before the first connection `sshd -T` fails without `/run/sshd` (`*sshd.EnvError`, [sshd-effective.md](sshd-effective.md) §4), so `Change.Before` is not established there and a port change is refused (`ErrListenersUnknown`) until the engine has another source for it (`ReadBound`'s answer is one candidate, though it does not say which program holds a socket). On a `*ListenerError` after `daemon-reload` the socket was not restarted, but the generator has already rewritten its configuration: roll the files back and plan the reverse change with `Rollback` (its own `daemon-reload`), under `context.WithoutCancel`.
- **`p2-revert`:** the journal's "services to reload" can hold the `Change` and replay `PlanFor` on rollback: `Change{Keywords, After: <what the restored files configure: Listeners.SSHD of sshd.Evaluate over them>, Rollback: true}`, which drops the new port on purpose and starts a unit the failed change left down (§2.6a). Set `Rollback` only when the undone change's gated step ran (`Report.Steps`). The confirmation should come from a connection to a listener the change added (`Plan.Adds`): one over a held port proves nothing about the new one, and the clean-up then drops the port that worked.
- **`p2-ufw`:** `ReadBound` is a bound-socket source ([sshd-effective.md](sshd-effective.md) §6); it does not say which program holds a socket.
- **`p2-sshd-migrate`:** `ReadSocketDropIns` finds v0.3.x's `listen.conf`; once it is removed (backup, printed note), `PlanFor` no longer refuses a socket host's listener change. The removal is itself a listener change for a user connected on `listen.conf`'s port: it takes effect at `daemon-reload` and the restart of `ssh.socket`. `Change` does not model it (it carries sshd_config keywords only, and on such a host `ReadEffective` reports the socket and sshd disagreeing, so `Before` is not `Known`); how that unit holds the old port and which `Change` it plans is its design.
- **`p3-output`:** `Report.Reason` is a stable code for why a change is not verified; the error sentinels above are the ones to map to registry codes.
- **`p2-pve`:** no port change on Proxmox VE (plan §3.18) is that unit's refusal; this one plans the `ssh.service` reload.
- **`p2-alpine`:** a `UsePAM`/Kerberos change (`ErrFlavour`) needs `rc-service sshd restart`, whose `stop_pre` runs `checkconfig`; whether sessions survive it is unverified.
- **Not modelled:** systemd's `socket.d/` drop-ins, which apply to every socket unit, and a `BindIPv6Only=` or `FreeBind=` setting: `systemctl show -p Listen` does not print them, so only the `ss` check after the restart sees their effect on the listeners (an IPv6-only `[::]` then fails it with `ErrNotBound`, after the socket was rebound); sshd's `rdomain` (neither `ss` nor `systemctl show` prints it, so listeners are compared by address and port only).
- **`sshd.ParseSocketListen`** is new API in `pkg/host/sshd`; [sshd-effective.md](sshd-effective.md)'s API list includes it since `next/p2-vmtest` brought that page up to date.
