# UFW: letting the SSH listeners through before the firewall can block them (`pkg/host/ufw`)

> **Unit:** refactor plan Phase 2, `next/p2-ufw` (decision §3.17, approved 2026-10-17: no UFW `disable`/`reset` sequence; brief §2 decision "Proxmox hosts: no UFW"; brief 2.2 "UFW: after making changes, check the rules with `ufw status verbose`"; brief 2.3 step 2, "firewall first"). V-numbers: V9 (origin/main allows only the configured port and runs `ufw disable` then `ufw reset` first), V10 (UFW enabled on Proxmox VE), the firewall half of V8 (the new port allowed before sshd moves; the order itself is `p3-engine`'s; its open approach, rules the user did not ask for, is [P-XX-ufw](../refactor/proposals.md#p-xx-ufw)) and of V12 (a socket host's listeners) ([side-effects.md](../refactor/phase0/side-effects.md)).
> **Status:** built and tested on macOS against the recording fake (`hostfake`) only, with ufw answered by a small model in the tests (`helpers_test.go`) written from ufw 0.36.2's sources (§3), not from output captured on a host. Nothing has run on Linux; §4 lists what is "written, not run (gate 5)".

`ufw.Read(ctx, sys, pve)` establishes UFW's state: `ufw status verbose`, `/etc/default/ufw`, `/etc/ufw/ufw.conf` and the saved rules in `/etc/ufw/user.rules` and `user6.rules`. `ufw.PlanFor(in)` is pure: from the effective SSH listener set (`sshd.ReadEffective`'s `Listeners`), the ports a change adds and that state, it returns `ufw allow <port>/tcp` for each port nothing lets through, then the default policies, then `ufw --force enable`, and refuses a plan after which an SSH listener that is reachable now, or a new port, would not be. `ufw.Execute(ctx, sys, plan)` runs the steps and checks `ufw status verbose`; `ufw.Rollback` runs the undo of what ran, stopping at the first that fails. `ufw.Check(state, needs)` is the cross-check for a status report. What ufw shows is its saved rules with its chains loaded; the only proof that new connections pass is the confirmation from a new session (brief 2.4).

## 1. Why

origin/main's firewall step sets the defaults, runs `ufw disable`, then `ufw reset`, then allows `cfg.SshPort` and pipes `yes` into `ufw enable` (side-effects row 19). It allows the *configured* port, never the ones sshd listens on (V9), so a stray `Port 22`, a `ListenAddress` with its own port or ssh.socket's listeners are blocked once ufw starts; a failure after `disable` leaves the firewall off with no rollback; and nothing stops it on Proxmox VE, where ufw competes with pve-firewall and blocks the web UI, corosync and migration (V10). A captured dry run allowed a different port from the configured SSH port ([phase0-findings.md](../refactor/phase0-findings.md) §3.3). Brief §3 principle 1: never lock the user out.

## 2. Guarantees

### Reading (`Read`, `ParseStatus`, `ParseTuples`)

1. **Proxmox VE is never touched.** With `detect.Proxmox.Installed` Yes, `Read` runs nothing and returns `ErrNotApplicable`; `PlanFor` returns a `NotApplicable` plan, and `Execute` runs nothing for it. A Proxmox fact that is not established is `ErrProxmoxUnknown` (wrapping detect's reason), never "not Proxmox": V10 is critical. Tested: no call is recorded on the fake.
2. **Read-only.** `Read` runs exactly `ufw status verbose`, reads `/etc/default/ufw` and `/etc/ufw/ufw.conf`, stats `/proc/sys/net/ipv6`, and reads `user.rules` and, when ufw's IPv6 is on, `user6.rules` (tested: no other call). ufw missing (`host.ErrNotFound`) is `State{}` with `Installed` false; a failing command or read is an error (tested for each file, and a stat that fails other than not-exist); content it cannot read goes to `Bad`, and `State.Known()` is false.
3. **What ufw shows and what is saved.** `ufw status verbose` says active when ufw's user chains exist (`Status: inactive` when `iptables -L ufw-user-input` exits 1) and, while active, prints the logging level, `Default: <in> (incoming), <out> (outgoing), <routed> (routed)` and the rules, all from its saved files and settings: the rules of its saved lists, IPv4's then IPv6's, each in order. It does not show what the kernel's chains hold rule by rule: ufw's start creates the user chains before it restores `user.rules` and goes on after a failed restore, so a partial start reads as active with every saved rule (§3). Inactive, it prints nothing else, so the plan reads the saved rules themselves, the `### tuple ###` lines ufw loads when it starts, and the settings as ufw reads them (§2.4). A status row is split at its action (`ALLOW|DENY|REJECT|LIMIT` + `IN|OUT|FWD`): before it the To column (`[address] [ports[/proto]] [(application)] [(v6)] [on <interface>]` or `Anywhere[/proto]`), after it From, then a log type and `# comment`, which may hold anything (tested with `# x11 ALLOW IN y`). A saved rule's destination application is kept (`Rule.App`): ufw tells `allow OpenSSH` from `allow 22/tcp` by it.
4. **Settings as ufw reads them.** `/etc/default/ufw`, then `/etc/ufw/ufw.conf`, each line as ufw's `_get_defaults` reads it, a key of `ufw.conf` winning (tested: its `IPV6=no` and `DEFAULT_INPUT_POLICY` win). `State.Enabled` is `ENABLED=yes` (`is_enabled()`): ufw starts at boot, and its commands change the loaded chains as well as the saved files. `State.IPv6` is `IPV6=yes` and the kernel's `/proc/sys/net/ipv6`, ufw's own `use_ipv6()`; without it ufw adds IPv4 rules only and, once started, drops all IPv6 but loopback. `State.NoKernelIPv6` is that directory missing: no IPv6 connection can arrive at all (§3).

### Planning (`Needs`, `Evaluate`, `PlanFor`, pure)

5. **The effective listener set, not the configured port.** `Needs` lists every listener of sshd's `listenaddress` lines and of `ssh.socket`'s `Listen` set (a socket's `[::]` is dual-stack, systemd's default, so it also needs IPv4; sshd's own `[::]` is IPv6 only, §3), then `Input.Add` (the port the change adds) and `Input.Keep` (ports the configuration does not show, such as the current session's) in each IP version the listeners use. `Listeners.Known` false is `ErrListenersUnknown`, so nothing is enabled or narrowed on an incomplete set ([sshd-effective.md](sshd-effective.md) §6).
6. **A verdict per need, as ufw's chains decide.** `Evaluate(rules, Firewall{Active, IPv6, NoKernelIPv6, Incoming}, needs)`. In each family's list, in order, the first rule that matches TCP to the port wins ("Rule ordering is important and the first match wins", ufw(8)): an unrestricted `allow` is `Allowed`, `limit` `Limited` (accepted, rate-limited per source), `deny`/`reject` `Denied`. A rule restricted by source, interface or one destination address only restricts: an earlier restricted allow makes a later unrestricted deny, or a default deny, `Restricted` (an allowlist: accepted for some sources only); an earlier restricted deny makes a later unrestricted allow, or a default allow, `Excepted` (a blocklist: accepted from everywhere but some sources). No match: the default incoming policy decides (`allow` is `Allowed`, `deny`/`reject` `Blocked`). Inactive ufw accepts everything (its stop sets every policy to ACCEPT, §3). While active, a loopback listener (`127.0.0.0/8`, `::1`) is `Allowed`: `before.rules` and `before6.rules` accept `lo` before any user rule, so the plan never opens a port for it (§3). IPv6 on a kernel without IPv6 is `Unreachable`; IPv6 with ufw's IPv6 off is `Blocked`. A port list, range or address it cannot read is `VerdictUnknown`, never a pass. `Verdict.OK()` is `Allowed`, `Limited` or `Unreachable`: nothing to let through. `Excepted` is not OK: this package cannot tell whether the session's own address is among the exceptions. Tested case by case (`TestVerdict`).
7. **Rules first, then the policy, then enable; never `disable` or `reset`.** A port gets `ufw allow <port>/tcp` when, with ufw active and the planned default policy, nothing lets it through (`Blocked`), even if ufw stays inactive, so a later `ufw enable` by hand keeps it open; `Desired.NoSaveWhileInactive` turns that off for a ufw that stays inactive (V8's open approach, [P-XX-ufw](../refactor/proposals.md#p-xx-ufw)). Then `ufw default <policy> incoming|outgoing` for each `Desired` policy that differs, then `ufw --force enable` when `Desired.Enable` and ufw is inactive: ufw(8) says enabling flushes its chains and that SSH should be allowed before it. No step runs `ufw disable` or `ufw reset` (tested over every plan in `TestPlanFor` and `TestPlanForRules`); `ufw disable` exists only as the undo of the plan's own enable.
8. **Rules already there are never repeated, changed or removed.** `ufw allow <port>/tcp` writes a rule for IPv4 and, with ufw's IPv6 on, IPv6, whichever families the listeners use. So a port gets no rule when, in any family it writes, the allow would change a saved rule: the port is `Denied`, `Restricted` or unreadable from anywhere there (the allow would widen an administrator's restricted rule, or turn a deny round, for the other family's sake), or a saved rule has the allow's tuple but another action, log type or comment (`limit 22/tcp`, `deny 22/tcp`, a commented `allow 22/tcp`), which ufw replaces with the allow instead of adding one and, while inactive, answers "Rules updated", so that its undo would delete the administrator's rule (§3). An application rule (`limit OpenSSH`) is another tuple and is left alone. A need left `Blocked` on such a port says why in its `By` ("no rule added: `ufw allow 22/tcp` would change …") and is refused or reported as §2.9 says. Tested: a deny in IPv4 only on an active host, a deny in IPv6 with IPv4 listeners, a limit and a commented allow in IPv4 only, `limit OpenSSH`.
9. **Refused when the plan would block a listener (`*BlockError`, `ErrBlocks`).** After the steps, every need is evaluated again under the saved rules: one that is not OK then, while it is now (ufw inactive, or let through by the saved rules ufw shows as loaded), or a new port, refuses the whole plan with the needs, their verdicts and the deciding rule. So a saved deny, a saved restricted allow, a saved blocklist (`Excepted`), a rule the allow would change (§2.8), or `IPV6=no` with sshd on `[::]:22`, all of which take effect only when ufw starts, are refused before anything runs (tested). A listener that is already not let through and stays so is a pre-existing state, not caused by the plan: it is a `Finding`, and the plan goes ahead (tested). With ufw inactive and staying so, each need its saved rules would not let through once ufw starts is a `FindingAtStart` (`ssh-not-allowed-at-start`), not a refusal, since nothing the plan runs blocks it (tested: a new port under a saved deny). A new port the plan lets through from anywhere while a listener of the same IP version is `Restricted` or `Excepted` is a `FindingWidened` (`ssh-new-port-wider`): moving SSH there widens who can reach it; whether to mirror the restriction or refuse is [P-XX-ufw](../refactor/proposals.md#p-xx-ufw) (tested). **ENABLED and the chains disagree: refused (`ErrEnabledMismatch`).** Enabled but stopped (on Alpine after a reboot without a runlevel, §6, or after a failed start), each `ufw allow` saves its rule and then fails ("Could not update running firewall"), and the next boot loads the saved rules; loaded but not enabled, an allow is saved and shown but not loaded (§3). Tested both.
10. **Idempotent.** With the rules, policies and state the plan leads to, the second plan is empty (`TestExecute2230`). Other `Desired` errors: a policy ufw does not have, a port 0 (`fs.ErrInvalid`); `ErrNotInstalled`; `ErrStateUnknown` for a line not read; `ErrEnabledMismatch`.

### Executing (`Execute`, `Rollback`)

11. **Steps in order, stop at the first failure.** A command's error is returned with its argv (`*host.ExitError` for ufw's exit 1 and `ERROR:` on stderr). The `Report` holds every step up to the failed one with its `host.Result`, and `Report.Undo`, the inverse commands of the steps that ran, last first (`ufw disable`, `ufw default <old> <dir>`, `ufw delete allow <port>/tcp`): the input to `Rollback` and to `p2-revert`'s journal. **A default or an enable is undone even when it failed:** ufw writes `DEFAULT_<CHAIN>_POLICY` before it restarts the firewall, and writes `ENABLED=yes` before it starts it, putting `ENABLED=no` back on a failed start without stopping what the start loaded (§3), so a failed step may have taken effect. Its undo puts back the state before it and is harmless when the step did nothing (`ufw disable` always runs ufw's stop). Tested with the model: a policy saved, then exit 1; an enable that exits 1 with the chains loaded; each rolled back. A failed allow is not undone (§2.12). `Plan.PreUndo()` are the plan's default and enable undos, last first, safe to journal before `Execute` runs (§6).
12. **An undo never deletes a rule hardn did not add.** An allow is undone only when ufw's answer is "Rule added"/"Rules updated" for every family and nothing else; "Skipping adding existing rule" (the rule was saved already) is not undone, and a mixed or unknown answer (ufw added IPv4's and skipped IPv6's; `ufw delete allow <port>/tcp` would delete both) is left, with `StepReport.Note` saying why: an allow rule left behind never locks anyone out (tested). A rule ufw would replace is never planned (§2.8), so "Rules updated" is never the answer to a replacement.
13. **Verified with `ufw status verbose`.** After the steps, the status must be read whole and show the planned state: active or not, the default incoming and outgoing policies, and every need the plan lets through let through by ufw's saved rules, its chains loaded (`ErrVerify` naming the need otherwise). This catches what an exit status does not: ufw answers a declined enable with "Aborted" and exit 0, and a policy can be answered and not applied (tested with the model, with a status not read whole after the steps, and with one that fails). The status cannot show that the kernel holds each rule (§2.3): `Verified` is ufw's word, and the proof that new connections pass is the confirmation from a new session (brief 2.4, `p2-revert`). Inactive by design, `Verified` stays false with `Unverified` "rules are saved, not loaded". `Report.Coverage` is each need's verdict under the status.
14. **Rollback stops at the first undo that fails** (a `*RollbackError`: the command, its error, which `Unwrap` gives, and `NotRun`, the undos after it). `Report.Undo` is last step first, so `ufw disable` and the policies' undos run before any `ufw delete allow`: going on after one of them failed would delete the SSH rules from a firewall that still drops what no rule accepts, which locks new connections out, while an allow left behind never does (tested: a failed `ufw disable` leaves ufw active with its four rules, and the two deletes not run). Every `host.System` method refuses a done context: after Ctrl-C pass `context.WithoutCancel(ctx)` (tested); a done context makes `Execute` run nothing (tested).
15. **Through `host.System` only.** Depguard rule `ufw-through-host` denies `os`, `io/ioutil`, `golang.org/x/sys`, `syscall`, `net` (except `net/netip`) and `plugin` to the package's non-test files (probed: an `os` import fails lint); `host-stdlib` keeps it to the standard library and `pkg/host/...`.

### The cross-check (`Check`)

16. `Check(state, needs)` evaluates the needs under `ufw status verbose` (ufw's saved rules and policies, with its chains loaded) and returns a `Finding` for each that is not `Allowed`, `Limited` or `Unreachable` while ufw is active: `ssh-not-allowed` (`Blocked` or `Denied`), `ssh-restricted`, `ssh-allowed-except` (`Excepted`), `ufw-unknown` (an unreadable rule, and a status not read whole). Inactive with `ENABLED=yes`, ufw starts at boot: each need its saved rules would not let through then is `ssh-not-allowed-at-start`. ufw not installed (`!State.Installed`) gives no coverage and no finding: the caller reports it as not configured, not unknown (tested). `Finding.Incoming` carries the default policy, so `p4-risk` can score "default deny and an SSH listener not allowed" critical (plan, `p4-risk` row). `FindingKind.String()` is the stable code; an out-of-range value reads "unknown", as `Verdict`'s and `StepKind`'s do (tested).

## 4. Written, not run (gate 5)

No `ufw` has run. On the Debian 13, Ubuntu 26.04 and Alpine 3.24 VMs (`next/p2-vmtest`) and an Ubuntu 24.04 host, as root:

- `ufw status verbose` and `user.rules`/`user6.rules` on each, stock and after `ufw allow OpenSSH` (Ubuntu's profile), `ufw limit 22/tcp`, `ufw allow from 192.0.2.0/24 to any port 22 proto tcp`, `ufw deny 2230/tcp` and an `in on eth0` rule: every row read (`Bad` empty) and the same verdicts from the status and the saved rules;
- the brief's 2230 scenario, ufw step first: `ufw allow 22/tcp`, `ufw allow 2230/tcp`, `ufw --force enable` with an SSH session open; **the session survives**, new connections to 22 and 2230 are accepted over IPv4 and IPv6, `Execute` reports `Verified`; then the sshd change and reload (`p2-reload`), a new connection on 2230, `Rollback` restoring the inactive firewall and no rules;
- on Ubuntu 26.04, `ssh.socket`'s dual-stack `[::]:22`: an IPv4 connection accepted once the IPv4 rule is there;
- `ufw default deny incoming` on an active ufw with an SSH session open (ufw stops and starts the firewall): the session survives;
- each answer `undo` reads ("Rule added", "Rules updated", "Skipping adding existing rule", with " (v6)"), and `ufw delete allow 22/tcp` running without a prompt;
- the replacement §2.8 rests on: `ufw allow 22/tcp` over a saved `limit 22/tcp` (and a commented `allow 22/tcp`) in IPv4 only replaces it, answered "Rules updated" while inactive and "Rule updated" while active;
- ufw's partial failures (§2.11), with a start made to fail (for example a `before.rules` that does not restore; how best to provoke it is **[unverified]**): `ufw default deny incoming` exits 1 with the policy saved, and `ufw --force enable` exits 1 with `ENABLED=no` and chains loaded; in each case `Rollback` (`ufw default allow incoming`, `ufw disable`) puts the host back, and `ufw status verbose` reads as §2.3 says;
- `Rollback` after a failed `ufw disable`: it stops, the allow rules stay;
- `ENABLED=yes` with ufw stopped (Alpine after a reboot, §6): `PlanFor` refuses with `ErrEnabledMismatch`, and `ufw allow` there exits 1 after saving the rule (expected, §3);
- `IPV6=no` with sshd on `[::]:22`: the refusal, and that ufw does drop IPv6 once started;
- a kernel booted with `ipv6.disable=1`: `/proc/sys/net/ipv6` missing, whether `sshd -T` still lists `[::]:22` **[unverified]**, and the plan neither refusing nor reporting IPv6;
- a loopback listener (`ListenAddress 127.0.0.1:2222` beside the public one): a connection over `lo` accepted under default deny, with no rule for it;
- a declined enable: `ufw enable` without `--force` under SSH with stdin on `/dev/null` (expected: "Aborted", exit 0), and whether OpenSSH ≥ 9.8's `sshd-session` process name defeats ufw's `under_ssh` check (irrelevant to `--force`);
- Alpine: ufw from the community repository; whether ufw comes back after a reboot without `rc-update add ufw default` (expected: not, §6);

## 5. API

```go
package ufw

const DefaultsFile, ConfFile, UserRules, User6Rules, KernelIPv6 = "/etc/default/ufw", "/etc/ufw/ufw.conf", "/etc/ufw/user.rules", "/etc/ufw/user6.rules", "/proc/sys/net/ipv6"

var ErrNotApplicable, ErrProxmoxUnknown, ErrNotInstalled, ErrListenersUnknown, ErrStateUnknown, ErrBlocks, ErrVerify, ErrEnabledMismatch error

func Applies(pve detect.Proxmox) error // nil, ErrNotApplicable, or ErrProxmoxUnknown

type Policy string // PolicyAllow, PolicyDeny, PolicyReject, PolicyDisabled; "" not established
type Family uint8  // IPv4 = 4, IPv6 = 6
type Rule struct { Action, Dir, Proto, Dst, DPort, Src, Iface, App string; Family Family; Line string }

type Status struct { Known, Active bool; Logging string; Incoming, Outgoing, Routed Policy; NewProfiles string; Rules []Rule; Bad []string }
type State struct { Installed bool; Status Status; Enabled, IPv6, NoKernelIPv6 bool; Incoming, Outgoing Policy; Rules []Rule; Bad []string } // Known() bool
func Read(ctx context.Context, sys host.System, pve detect.Proxmox) (State, error)
func ParseStatus(out []byte) Status
func ParseTuples(data []byte, fam Family) (rules []Rule, bad []string)

type Need struct { Port uint16; Family Family; Addr netip.Addr; New bool; Why string }
func Needs(ls sshd.Listeners, add, keep []uint16) []Need
type Verdict uint8 // VerdictUnknown (zero), Allowed, Limited, Restricted, Blocked, Denied, Excepted, Unreachable; OK() bool
type Coverage struct { Need Need; Verdict Verdict; By string }
type Firewall struct { Active, IPv6, NoKernelIPv6 bool; Incoming Policy }
func Evaluate(rules []Rule, fw Firewall, needs []Need) []Coverage // pure
type FindingKind uint8 // FindingNotAllowed "ssh-not-allowed", FindingRestricted "ssh-restricted", FindingUnknown "ufw-unknown",
// FindingExcepted "ssh-allowed-except", FindingAtStart "ssh-not-allowed-at-start", FindingWidened "ssh-new-port-wider"
type Finding struct { Kind FindingKind; Coverage Coverage; Incoming Policy }
func Check(st State, needs []Need) ([]Coverage, []Finding)

type Desired struct { Enable bool; Incoming, Outgoing Policy; NoSaveWhileInactive bool }
type Input struct { Proxmox detect.Proxmox; Listeners sshd.Listeners; Add, Keep []uint16; State State; Desired Desired }
type StepKind uint8 // StepAllow, StepDefault, StepEnable
type Step struct { Kind StepKind; Argv, Undo []string; Port uint16; Why string }
type Plan struct { NotApplicable bool; Steps []Step; Needs []Need; Before, After []Coverage; Active bool; Incoming, Outgoing Policy; IPv6, NoKernelIPv6 bool; Findings []Finding }
func (p Plan) Empty() bool
func (p Plan) PreUndo() [][]string // the default and enable undos, last first: journal before Execute
type BlockError struct { Coverage []Coverage } // Unwrap: ErrBlocks
func PlanFor(in Input) (Plan, error) // pure

type StepReport struct { Step Step; Result host.Result; Undo []string; Note string }
type Report struct { Steps []StepReport; Undo [][]string; Status Status; Coverage []Coverage; Verified bool; Unverified string }
func Execute(ctx context.Context, sys host.System, p Plan) (Report, error)
type RollbackError struct { Argv []string; Err error; NotRun [][]string } // Unwrap: Err
func Rollback(ctx context.Context, sys host.System, rep Report) error // stops at the first failure
```

## 6. Not in this unit; inputs to later units

- **`p3-engine`:** the order (brief 2.3): `Read` and `PlanFor` at plan time, so a refusal (`*BlockError`, `ErrListenersUnknown`, `ErrEnabledMismatch`) shows in a dry run; `Execute` before the sshd change is written; any error from it means `Rollback` under `context.WithoutCancel` while the session is open. Fill `Input.Keep` with the current session's server port (`SSH_CONNECTION`'s fourth field) when hardn runs over SSH: the listener set is configuration, so a port the running daemon still holds from before an unapplied change is not in it ([sshd-effective.md](sshd-effective.md) §2.5, §6). `reload.ReadBound` is not used to add rules: `ss -Htln` does not say which program holds a socket, and allowing every bound port would open other services. Whether hardn adds an allow rule the user did not ask for (V8's open approach: with the UFW SSH policy off, `enableUfwSshPolicy`, or with ufw inactive) is the maintainer's call, [P-XX-ufw](../refactor/proposals.md#p-xx-ufw); the engine follows it through whether it calls `PlanFor` at all and through `Desired.NoSaveWhileInactive`. `Plan.Findings` (§2.9) go into the plan's output beside the steps.
- **After the confirmation (brief 2.3 step 5):** dropping the old port's rule is not planned here. It is the clean-up change's: run the `ufw delete allow <port>/tcp` of the step that added it (`Report.Undo`), which exists only when hardn added that rule.
- **`p2-revert`:** journal `Plan.PreUndo()` before `Execute` (so a hardn killed after the enable still has `ufw disable`), then `Report.Undo` once it returns; replay the journal with `Rollback`'s rule, stopping at the first undo that fails (§2.14; `RollbackError.NotRun` is what is left). The change's risk class is lockout (firewall).
- **`p3-output`:** `ErrBlocks`, `ErrVerify` (`UFW_VERIFY_FAILED` in the plan's example), `ErrNotInstalled`, `ErrNotApplicable`, `ErrEnabledMismatch` and the finding codes (§2.16) to registry codes.
- **`p4-check-firewall` / `p4-risk`:** branch on `State.Installed` first (not installed is not configured; `Check` gives nothing for it), then `Check(state, Needs(listeners, nil, nil))` for the status; "default deny and a listener not allowed" is a `FindingNotAllowed` with `Incoming` deny. `ssh-allowed-except` (a blocklist) and `ssh-restricted` (an allowlist) are told apart so that they can be scored apart. On Proxmox VE the firewall status is `p2-pve`'s (pve-firewall, read-only).
- **`p2-alpine` / the firewall slice:** on OpenRC `ufw enable` does not add ufw to a runlevel (v0.3.2 ran `rc-update add ufw default`; origin/main does not; [side-effects.md](../refactor/phase0/side-effects.md) §4.4, §6), so it is not started at boot **[I]**, and the host is then `ENABLED=yes` and stopped, which `PlanFor` refuses (`ErrEnabledMismatch`) and `Check` reports at start; installing ufw is [P-16](../refactor/proposals.md#p-16).
- **The legacy firewall code** (`pkg/adapter/secondary/ufw_firewall_repository.go`, `pkg/application/firewall_manager.go`, `pkg/domain/service/firewall_service.go`) is untouched: its sequence (V9) stays until the firewall slice moves onto this package, and `next/p0-hazards` gates it meanwhile.
- **Not modelled:** rules outside ufw's user lists (`before.rules`, `after.rules`, other iptables or nftables users such as Docker) except the stock `before.rules`' loopback accept; routed rules; a `limit` rule's rate limit (counted as let through); sshd's `rdomain`; a socket's `BindIPv6Only=ipv6-only` (a socket `[::]` is taken as dual-stack); the init scripts' shell reading of the settings files, which `readDefaults` reads as ufw's Python does.
- **Size:** about 1,360 lines of Go outside tests (about 245 of them whole-line comments) and 1,290 of tests, against the plan's guideline of about 500: the unit reads two forms of the same rules (the status for what ufw shows, the saved tuples for an inactive ufw) and two settings files, evaluates them as ufw's chains do, works out which saved rules an allow would change, and its executor reads ufw's answers so that an undo never deletes a rule it did not add. The review fixes added about 270 lines of code and 340 of tests.
