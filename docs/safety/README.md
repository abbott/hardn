# Safety primitives (refactor plan Phase 2)

> **What this is:** the index of `docs/safety/`, one page per Phase 2 unit, written by `next/p2-vmtest`, with the open items the units hand to Phase 3 and later; `next/p2-revert-plans` added its page and closed two of the items. Each page says what its unit guarantees, the platform facts it relies on (with their sources), what is "written, not run" until the VMs exist (gate 5), and its API.
> **Status:** every primitive is built and tested on macOS against the recording fake (`pkg/host/hostfake`) and, for the file primitives, on real files inside temporary directories. **Nothing has run on Linux.** [vmtest.md](vmtest.md) is the sequence that runs them on the maintainer's VMs; until it has, every page's §4 stays "written, not run (gate 5)".

## Open items for Phase 3 and later

Each item names the page that hands it on; the page has the detail.

### `p3-engine`

- **The order.** Brief 2.3's ordering rule over the primitives is the engine's: detect, `sshd.ReadEffective`, `migrate.Find`/`PlanFor`/`Check`, `pve.PlanSSH`, `sshd.Validate`, `reload.PlanFor`, `ufw.PlanFor` at plan time, so every refusal shows in a dry run; then `revert.Arm`, the firewall, backups, the write, the reload, the effective-value check, `revert.MarkApplied` ([reload.md](reload.md) §6, [ufw.md](ufw.md) §6, [sshd-migrate.md](sshd-migrate.md) §6, [revert.md](revert.md) §7). `internal/tools/p2drive` is a worked sketch of that order for four changes ([vmtest.md](vmtest.md) §2), not the engine. *Closed*: the stages and the plan-time refusals by `next/p3-engine` ([engine.md](../engine/engine.md) §2.5, §2.6), the primitives in that order at plan time by `next/p3-steps` ([steps.md](../engine/steps.md) §2.1, §2.6).
- **Journal what already ran under a context of its own; hold signals around the rollback.** The `Record` after a step that ran (ufw's `Report.Undo`, the `ssh` reload without `IfUp`, revert.md §7 items 2 and 3) must be written after Ctrl-C too, so under `context.WithoutCancel` with a bound: with the command's context it fails once Ctrl-C has cancelled it, and the rollback then works from a journal that still says `IfUp`, so a unit the interrupted reload stopped is never started. The in-process rollback runs with `SIGHUP` and `SIGINT` ignored, as `cmd/hardn`'s `holdSignals` does for `hardn rollback`, since `host.Real`'s children share the caller's process group. The driver does both ([vmtest.md](vmtest.md) §2.6, §2.7). *Closed by `next/p3-engine`* ([engine.md](../engine/engine.md) §2.4, §2.12).
- **An in-process rollback that did not finish stops the timer all the same** (`Rollback` with `ReasonFailed`, [revert.md](revert.md) §2.14 step 4): nothing then takes it up but `hardn rollback <id>`, which its error names. Whether `Rollback` should leave the timer when it returns `ErrIncomplete` is `p2-revert`'s design to revisit with the engine. *Closed by `next/p3-engine`*: it keeps stopping it, a decision ([engine.md](../engine/engine.md) §2.13).
- **A port change must reach a listener.** A `ListenAddress` with its own port ignores every `Port` line, so the new port must be in `reload.Plan.Adds` before anything changes, and after the reload in `sshd -T`'s listeners, not only in its Port set. A migrated v0.3.2 `00-hardn.conf` keeps `ListenAddress 0.0.0.0:2230`, so this is the R8 path ([vmtest.md](vmtest.md) §2.3). *Closed by `next/p3-steps`* ([steps.md](../engine/steps.md) §2.13).
- **`reload.Execute`'s `ErrInUse` check belongs to the plan too**: it runs before Execute's first step, after the timer is armed and the firewall changed. The driver runs it at plan time through `Execute` with a plan of no steps; the engine wants it exported as a check of its own ([reload.md](reload.md)). *Closed by `next/p3-steps`*: `reload.CheckFree`, run at plan time ([steps.md](../engine/steps.md) §2.11).
- **`migrate.Apply` takes its own backups** and writes with no point between the two where the engine could `Record` them, so its `Report.Backups` can be journalled only after the files changed, against revert.md §7 item 1. The driver backs up `Plan.Sources` itself, journals those, and lets `Apply` back them up again in the same run. Either `Apply` gains a hook before its first write, or it takes backups the engine has already taken ([sshd-migrate.md](sshd-migrate.md) §6). *Closed by `next/p3-steps`*: it takes the engine's (`migrate.Options.Taken`), no hook ([steps.md](../engine/steps.md) §2.7).
- **Use the registered plan rollbacks** (closed for the merge's gap by `next/p2-revert-plans`: `cmd/hardn`'s `revertPlans` is `plans.Registry()`, [revert-plans.md](revert-plans.md) §2.1 to §2.7). Pass `plans.Registry()` to `Arm`, `Record` and `Rollback`, and journal each unit's change with `plans.PVEKeys`, `Sudoers`, `DNS` or `Alpine` before the unit's apply ([revert.md](revert.md) §7, [pve.md](pve.md) §6): `Record` checks only that a plan step's unit is registered, not its payload, so a step built otherwise is found only by the rollback. After an apply refused before it wrote anything, drop the plan step from the journal before ending the change, for every unit: DNS's and Alpine's rollbacks cannot tell their own change from the same one made since, and sudoers' would fail on the refusal's cause; each unit signals "wrote nothing" its own way ([revert-plans.md](revert-plans.md) §6, [dns.md](dns.md) §6, [alpine.md](alpine.md) §6). The journalled form of each plan is its Go type as `encoding/json` writes it, pinned by `TestWireFormat`'s `testdata/<unit>.json`: Phase 3's refactor of those types must keep it, or move the journal to a format of its own. *Closed*: `plans.Registry()` by default, an unregistered unit refused at plan time and an empty `Ran.Rollback` by `next/p3-engine` ([engine.md](../engine/engine.md) §2.4, §2.6); the four units' changes, made with their step functions, and each unit's "wrote nothing" by `next/p3-steps` ([steps.md](../engine/steps.md) §2.10). The types are unchanged (`TestWireFormat` passes).
- **A `listen.conf` migration on a socket-activated host rolls back** (closed by `next/p2-revert-plans`, [revert-plans.md](revert-plans.md) §2.8, §2.9): journal its reload with `After` = `migrate.Plan.Listening.All` and `socketDropIns` = the drop-ins the plan removes, which the rollback passes as `reload.Change.RestoredDropIns` ([reload.md](reload.md) §2.4, [sshd-migrate.md](sshd-migrate.md) §6).
