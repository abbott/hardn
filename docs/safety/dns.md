# DNS resolvers (`pkg/host/dns`)

> **Unit:** refactor plan Phase 2, `next/p2-dns` (brief 2.5 "DNS"; plan row `p2-dns`; findings [§12](../refactor/phase0-findings.md#12-proposed-adjustments-to-the-brief) row 25). V-numbers: V19 (`resolved.conf` overwritten wholesale and systemd-resolved restarted, an empty nameserver list accepted, `lan` forced, NetworkManager not detected, the direct path writing through the `/etc/resolv.conf` symlink; [side-effects.md](../refactor/phase0/side-effects.md) rows 21-23). The DNS screen is slice 2, the pilot of the full flow; this unit is the primitive under it.
> **Status:** built and tested on macOS against the recording fake (`hostfake`) only. `systemctl` and `resolvectl` are modelled by a test handler that follows systemd's sources (§3); nothing was captured from a host. Nothing has run on Linux; §4 lists what is "written, not run (gate 5)". Since `next/s2-control` the DNS control calls it ([control-dns.md](../engine/control-dns.md)), which nothing in `cmd/hardn` calls yet, so no behaviour changes today.

`dns.Read` establishes what manages `/etc/resolv.conf` and what it holds, `dns.Validate` checks a requested configuration, `dns.PlanDNS` plans the change (pure), and `dns.Apply` runs the plan over `host.System`, backing each file up first, checking that each step took effect and undoing the steps it ran when one fails; `dns.Rollback` undoes a plan.

## 1. Why

origin/main picks one of three strategies and applies it with no validation and no backup: when `systemctl is-active systemd-resolved` succeeds it overwrites `/etc/systemd/resolved.conf` with `DNS=<list>` and `Domains=lan` and restarts the service; when `which resolvconf` succeeds it writes `resolvconf`'s `head` and runs `resolvconf -u`; otherwise it writes `/etc/resolv.conf` in place, through a symlink. An empty list gives `DNS=` or a file with no nameserver (V19; [v032-reference.md](../refactor/phase0/v032-reference.md) §4.5 for v0.3.2, which panicked instead). Brief 2.5 asks to configure the manager when `/etc/resolv.conf` is a symlink; the audit adds that a regular file is not necessarily unmanaged either (findings §12 row 25).

## 2. Guarantees

### Reading (`HostOf`, `Read`)

1. **From detect's facts, never re-detected** ([detect.md](detect.md)). `HostOf` refuses, before anything is read, a distribution not established (`ErrUnknown`, wrapping detect's error), one that is not of the Debian, Ubuntu, Alpine, Proxmox VE or EL family (Rocky Linux, AlmaLinux and RHEL, whose `resolv.conf` is reported, [el-readonly.md](../engine/el-readonly.md)) (`ErrUnsupported`), and a container, detected (`ErrContainer`: the container manager provides the file, a decision of this unit) or not established (`ErrUnknown`). It checks the family only, not the release: Ubuntu 25.10 or Proxmox VE 8 (out of scope for `detect.Support`) pass, since the support gate is `p3-engine`'s (§6). It keeps whether systemd booted the host: Yes only for systemd with its run directory, No for OpenRC (detect found no systemd run directory), Unknown otherwise. Tested: `TestHostOfRefuses` (no call is made), `TestReadManagers`.
2. **Reads only.** `Read` makes `Lstat`, `Readlink`, `ReadFileNoFollow`, `Stat`, `ReadDir` and `ReadFile` calls and runs three queries: `systemctl is-active systemd-resolved.service` (on a host systemd booted only) and, for systemd-resolved, `resolvectl --no-pager dns` and `resolvectl --no-pager domain` (with no other argument, which only shows; with arguments they would set). Tested: `TestRead` fails on any other call, for each platform's stock layout.
3. **The manager**, in this order (the order of hex-migration 948b040's detector, plan §6, taken as an idea: a link's target first, then what the file says, then what runs):

   | `/etc/resolv.conf` | systemd-resolved | Manager | hardn |
   |---|---|---|---|
   | link to `/run/systemd/resolve/stub-resolv.conf`, `/run/systemd/resolve/resolv.conf` or `/usr/lib/systemd/resolv.conf` (a relative target is resolved against `/etc`) | any | `systemd-resolved` | writes its drop-in, never the file; refuses when resolved is not running (`ErrNotRunning`) |
   | link to `/run/resolvconf/resolv.conf` | any | `resolvconf` | reports (`ErrManaged`) |
   | link to `/run/NetworkManager/resolv.conf` or `no-stub-resolv.conf` | any | `networkmanager` | reports |
   | link to anything else | any | `foreign` | reports: never written through |
   | regular file whose first line is `# Generated by NetworkManager` / `# Generated by resolvconf` | any | `networkmanager` / `resolvconf` | reports |
   | other regular file, or none | active | `foreign` (resolved reads the file as another package's) | reports |
   | other regular file, or none | not running, or no systemd | `proxmox` on Proxmox VE, else `file` | writes the file |
   | anything else (a directory), or a fact not established | | `unknown` | refuses (`ErrUnknown`) |

   The 948b040 detector also treated a running NetworkManager (`nmcli general status` saying `running`) and an installed `resolvconf` (`resolvconf --version`) as the manager; this one does not. NetworkManager with `dns=none` runs without writing the file (§3), so this unit relies on the `# Generated by NetworkManager` header NetworkManager writes into its own file; an installed `resolvconf` does not say it writes the file either. A transitional state (`activating`, `deactivating`, `maintenance`), which detect maps to Unknown, and any word that is not a state systemctl documents are Unknown, never "not running". Tested: `TestReadManagers`.
4. **What the manager holds.** For a file: the address of every `nameserver` line and the last `search` or `domain` line, as glibc reads them (keyword at the start of the line, §3; `ParseResolvConf`). For systemd-resolved: whether `/etc/systemd/resolved.conf.d` is a directory, hardn's drop-in, and the drop-ins sorting after hardn's that assign `DNS=` or `Domains=` (`Later`, each an `Override` saying which). For each name only the file systemd reads is looked at: the first of `/etc`, `/run`, `/usr/local/lib`, `/usr/lib` that has it, and none when that one is a link to `/dev/null` (a mask); hidden files are skipped, as systemd skips them. Each file is read as systemd's parser reads it: blanks around the key and the value (`DNS = x` is `DNS=x`), comments starting with `#` or `;`, a trailing backslash continuing the line; keys are case-sensitive; an assignment in any section counts, which fails closed. Then the global, delegate and per-link servers `resolvectl dns` lists and the global and per-link search domains `resolvectl domain` lists (`~` marking a route-only one), wrapped lines included; each link's domains are kept on its `Link` (`Link.Domains`, matched by index and name, a link with domains and no servers added), for the status and the DNS screen's Search Domains row, and are never written (`next/s2-control`, the defect gallery-dns.md §8 item 4 recorded: they were dropped; `TestReadLinkDomains`). Output in any other form (a colour code, a line it does not print) is Unknown with `detect.ErrUnrecognised`, never an empty list (`TestReadResolvectl`, `TestReadLaterDropIns`). For a file, on every distribution: whether `dhclient` or `dhcpcd` is in `host.SearchPath` (`TestRead`, Alpine and Proxmox VE rows included). On Alpine also: `/etc/udhcpc/udhcpc.conf`, read as plain shell assignments (any other line makes it Unknown, since the script sources it), and udhcpc's hooks: each executable regular file (a link to one included, hidden names skipped) in `/etc/udhcpc/{pre,post}-{deconfig,bound,renew}`, which the script runs around each event (`TestReadUDHCPC`, `TestReadUDHCPCHooks`). And **whether udhcpc is the DHCP client in use** (`UDHCPC.InUse`, `next/s2-udhcpc`, the maintainer's decision of 2026-10-23: "report DNS_UDHCPC and ask udhcpc's question only when udhcpc is the DHCP client in use"): ifupdown-ng's DHCP executor `/usr/libexec/ifupdown-ng/dhcp` must be an executable file holding the order of §3 (`DHCPExecutorRule`), and no file of the networking service in `/etc/conf.d` (`networking`, `networking.<runlevel>`, `networking.<iface>`) may name another interfaces file; then each interface of `/etc/network/interfaces` (a regular file once links are followed) that uses DHCP (a `dhcp` word on its `iface` line, `use dhcp`, or a `dhcp-*` property) runs its `dhcp-program` (`udhcpc`, `dhcpcd` or `dhclient`, exactly; a property is named as the executor's environment names it, so `dhcp_program` and `DHCP-PROGRAM` count), else the first of `/sbin/dhcpcd`, `/usr/sbin/dhclient`, `/sbin/udhcpc` that `[ -x ]` takes as root (`Stat`, following links: `/sbin/udhcpc` is busybox's link; a regular file with an execute bit). **Yes** when an `auto` interface runs udhcpc (the networking service brings up those alone); **No** when it is established that none does (no interface on DHCP, each running another client or none found) and no udhcpc pid file (`udhcpc.*.pid`) is in `/var/run`; **Unknown** otherwise, with why in `UDHCPC.InUseErr`: the executor absent, not executable or holding another order (the choice is then not ifupdown-ng's as read, and busybox's own `ifup` is not modelled), a networking file in `/etc/conf.d`, the interfaces file unread or not a regular file, a line hardn does not follow (a backslash, carriage return or NUL; a line longer than 4094 bytes; `source`, `source-directory`, `template`, `inherit`, `inherits`, `defaults`, the interface named `defaults` (`auto defaults`), `auto` with no name; a property name with `=`; any other line naming udhcpc, such as `post-up udhcpc …`), a `dhcp-program` of another value or given twice otherwise, a client path that is there but not a regular file, an interface on DHCP through a `dhcp-*` property alone with `/etc/network/ifupdown-ng.conf` present (it can turn that off, and is not read), an interface that is not `auto` running udhcpc (brought up by hand, by a `networking.<iface>` service or as another's dependency), or a udhcpc pid file where the configuration starts none (udhcpc may still run: `dhcpcd` installed since boot, or another interfaces file). `Read`, `Stat` and `ReadDir` only, no command (`TestReadUDHCPCInUse`, the rule's table: stock Alpine Yes; the cloud image with dhcpcd No; `dhcp-program udhcpc` despite dhcpcd Yes; each Unknown case but an I/O error; `TestUDHCPCUnknownSource`: the finding names the file that left it Unknown). Where an interface running udhcpc runs it with another script than its default (a `dhcp-script`, legacy `script`, or `udhcpc-opts` or `dhcp-opts` that may name one: `-s`, `--script` or a prefix of it, or anything `eval` expands), `udhcpc.conf`'s `RESOLV_CONF` does not decide its rewrite: `UDHCPC.Rewrites` is Unknown, with why in `UDHCPC.Err` (`TestUDHCPCScript`). Like `UDHCPC.Err`, `InUseErr` is a finding, and a plan's refusal only where the plan is asked to stop udhcpc (`UDHCPCNoResolv`), whatever `udhcpc.conf` holds. `State.UDHCPCStoppable()` is the rule for asking whether to stop it: Alpine, a file, `InUse` and `Rewrites` Yes (`TestUDHCPCStoppable`). What could not be read is joined in `State.Err`; udhcpc's own error is kept apart in `UDHCPC.Err`, since it only matters to a plan that changes that file. `State.Findings()` (pure) gives the findings of item 9 from a `State` alone, for a check on a host whose plan is refused (`TestStateFindings`).

### Validation (`Validate`, pure)

5. **No empty list (V19)**: no nameserver is `ErrNoNameservers`. Each entry must be a plain IPv4 or IPv6 address (`net/netip`): a host name, a port, a zone (`fe80::1%eth0`), an IPv4-mapped IPv6 address, the unspecified address and multicast are refused; so are `0.0.0.0/8`, never a destination (RFC 6890), the limited broadcast address `255.255.255.255`, which a socket cannot send to without `SO_BROADCAST` (ip(7)), and IPv6 link-local, which needs the interface a zone would name (ipv6(7), `sin6_scope_id`) while zones are refused (IPv4 link-local, `169.254.0.0/16`, is accepted); and so is an address given twice (after canonicalisation: `2001:DB8:0::0053` is `2001:db8::53`). For a file manager, more than three is refused (glibc and musl use the first three and ignore the rest, §3); on systemd-resolved its own stubs `127.0.0.53` and `127.0.0.54` are refused (a loop), where a file may name a local resolver on loopback.
6. **Search domains are kept unless asked.** Without `ReplaceSearch`, the host's search domains are left exactly as they are: the file's `search` and `domain` lines, or the `Domains=` lines of the drop-in hardn wrote before. hardn adds none of its own: origin/main's forced `lan` is gone, and what the DNS screen offers by default is slice 2's decision (plan, slice table: "`lan` default"). With it, each domain must be a host name (labels of letters, digits and hyphens, 1 to 63 bytes, not starting or ending with a hyphen, 253 bytes at most, no trailing dot; systemd-resolved's route-only `~` domains are refused), with no repeat, compared ignoring case; an empty list removes them. `Search` given without `ReplaceSearch` is refused rather than ignored, so a caller that forgets the flag learns it. For a file the `search` line must fit musl's 255 bytes (it skips a longer line whole, §3), and on Proxmox VE only one domain is accepted, since its node DNS settings keep only the first (§3). Tested: `TestValidate`.

### Planning (`PlanDNS`, pure)

7. **systemd-resolved: a late drop-in that resets.** hardn writes `/etc/systemd/resolved.conf.d/zz-hardn.conf` (0644, root) and never `/etc/resolv.conf`:

   ```
   # Written by hardn: the system DNS servers for systemd-resolved.
   # An empty assignment resets the list that earlier files built.
   [Resolve]
   DNS=
   DNS=192.0.2.53 2001:db8::53
   Domains=                      (only with ReplaceSearch)
   Domains=example.net           (only with ReplaceSearch and domains)
   ```

   **The plan row's "last file wins" holds for single-value options only.** For a list option such as `DNS=` or `Domains=`, systemd collects the entries of every file in order, and an empty assignment clears what came before (§3). So the drop-in must sort last **and** reset each list it sets; then the main `resolved.conf` and every earlier drop-in can neither add to nor remove from it. `TestApplyResolved` seeds `DNS=` and `Domains=` in the main file and in an earlier drop-in and finds only hardn's lists afterwards, but that shows the tests' model of resolved (`world.load`, written from the sources in §3), not resolved: on a host this is gate 5's (§4). Names sort in C byte order across all four directories, and `zz-` sorts after every name that starts with a digit, an upper-case letter or `a` to `y`: after all names in systemd's recommended `60`-`90` range for `/etc`. A drop-in that still sorts later (`zz-i…`, `zzz-…`, `~…`) and assigns `DNS=`, or `Domains=` when the plan sets the search domains, refuses the plan with `ErrOverridden`, naming it: it would add to or reset hardn's list, and the change could not take effect. One that assigns only `Domains=` does not refuse a plan that keeps the search domains, since hardn's drop-in then changes no `Domains=`. Anything at hardn's path that is not a regular file (a `/dev/null` mask) is refused with `ErrDropInBlocked`. The reload is planned when the drop-in changes, when resolved's global servers are not the asked-for ones, or, with `ReplaceSearch`, when its global search domains (compared ignoring case) are not. Then `systemctl try-reload-or-restart systemd-resolved.service`: a reload where the unit supports it (systemd 256 and later: Debian 13, Ubuntu 26.04), a restart where it does not (Debian 12, Ubuntu 24.04), and nothing if resolved stopped meanwhile, which the check after it catches (§3). Per-link servers are reported (item 9).
8. **A file: the nameserver lines are replaced, every other line is kept.** The new `nameserver` lines take the place of the first old one (or are appended), so comments, `options`, `sortlist` and, without `ReplaceSearch`, the `search` and `domain` lines stay where they were; with it, one `search` line takes the place of the first of them. The file keeps its mode and owner; a new one is 0644, root. On Alpine, with `UDHCPCNoResolv` (and only then: an explicit plan step), `RESOLV_CONF="no"` is written to `udhcpc.conf` first, replacing its first `RESOLV_CONF` line and dropping later ones, or appended; the option is refused on any other host (`ErrNotApplicable`), and on Alpine where udhcpc is not the DHCP client (`UDHCPC.InUse` No: `ErrNotApplicable`) or where that is not established (Unknown: `ErrUnknown`, wrapping `InUseErr`), as where its rewrite is not (`ErrUnknown`, wrapping `UDHCPC.Err`). *Decided in `next/s2-udhcpc`, by "never claim, never surprise":* refused, not written as asked, since the step's own words ("udhcpc rewrites /etc/resolv.conf … on each lease") would claim what the host does not show, and the question is asked only where `InUse` is Yes, so the option reaches a plan elsewhere only when the host changed after the question or from a caller that did not ask it; nothing is written either way. Tested: `TestPlanFile`, `TestPlanFindings`, `TestReadUDHCPCInUse` (the plan with `UDHCPCNoResolv` on each `InUse`).

With `/etc/resolv.conf` linked to the uplink file, programs that read it bypass resolved and use its first three servers |

Also, asked or not, one per udhcpc hook (its path), which may rewrite the file whatever `RESOLV_CONF` says. None where udhcpc is not the client (`InUse` No), hooks included |

10. **Refusals**, before anything changes: a manager not established (`ErrUnknown`) or not hardn's to write (`ErrManaged`, naming the manager and the link target or first line), any unread fact (`ErrUnknown`, wrapping why), systemd-resolved not running (`ErrNotRunning`), `ErrOverridden`, `ErrDropInBlocked`, and what `Validate` refuses (`TestPlanRefuses`, a directory at `/etc/resolv.conf` and a zero `State` included). A configured host plans nothing (`TestPlanFile`'s second plan; the second plan after each `Apply`). Every step is a no-lockout change: no confirm-or-revert timer, and a failure is undone (brief 2.4).

### Applying (`Apply`, `Rollback`)

11. **Before anything changes, `Apply` refuses** a done context, a plan that is not what `PlanDNS` makes from its own `From` and `Want` or whose `From` names a manager its entries do not give (`fs.ErrInvalid`: a journal edited by hand can neither write other bytes nor pick another manager), a plan that writes a file with no `Options.Backups` (`ErrNoBackup`), and a host that differs from `From` in anything a step depends on (`ErrChanged`; `/etc/resolv.conf` turned into a link since the plan is such a change). Then each file the plan writes is backed up through `p2-atomic` (`backup.RollbackRequired`, so even with `enableBackups: false`, §3.16), and the copy must be what `From` read (absent, or the same SHA-256), else `ErrChanged`. Tested: `TestApplyRefuses` (a re-read that fails, a backup that fails and a file changed while it is backed up included; nothing is written outside the backup run).
12. **Each step is checked.** Each file step re-reads its path first and refuses, without acting, one that changed since (`TestApplyChangedDuringRun`), writes with `WriteFileAtomic` (which refuses a symlink, so a link is never written through even if one appears), and reads it back: content, mode and owner. After the reload, `resolvectl dns` must list exactly the asked-for nameservers as global ones, in order, and with `ReplaceSearch` `resolvectl domain` the asked-for search domains; a reload that succeeds without that (an assignment rejected by resolved's parser, which only logs a warning, §3) is `ErrNotEffective`. The drop-in directory is created only when it was not there, then set to 0755 whatever the umask (`MkdirAll` applies it, and systemd-resolved runs as `systemd-resolve`, §3) and read back. Tested: `TestApplyFails` (a file reading back with another mode, the search domains rejected), `TestApplyResolved` (the `chmod`).
13. **Recoverable.** When a step fails, every step that acted, the failed one included, is undone last first under `context.WithoutCancel(ctx)`, bounded by `Options.RestoreTimeout` (`DefaultRestoreTimeout`, two minutes), so a Ctrl-C mid-way still undoes. A file that holds what the step wrote gets its old content, mode and owner back, or is removed when there was none, and the drop-in directory is removed when the plan created it and it is empty; then, when a reload acted, `systemctl reload-or-restart systemd-resolved.service` runs, which reloads a running resolved and starts a stopped one (the forward restart on systemd 252/255 may leave it failed; `From` found it running), and resolved must list the old global servers and search domains again. A plan that only reloads (hardn's drop-in already on disk, not yet loaded) has no file to put back and nothing to reload back to: its reload is not run again, resolved is only started if it no longer runs, and the same check decides. `Result.Done` lists the steps that acted; `Result.Restored` says the undo completed and was checked, otherwise the error wraps `ErrNotRestored`: a reload-only plan whose reload loaded new lists is not Restored, since what resolved used before cannot be loaded back. `Result.Backups` names the copies. Tested: `TestApplyFails` (the reload failing, the restart leaving resolved failed, the reload without effect, the search domains rejected, Ctrl-C during the reload, `MkdirAll` failing, the undo's reload failing or without effect, which are not Restored, a write failing, a file reading back otherwise, the second of two writes failing), `TestApplyReloadOnly`.
14. **`Rollback(ctx, sys, plan)`** undoes a plan the same way, each step only when its effect is there: a file holding anything other than what the plan wrote is left alone (`ErrChanged`, wrapped in `ErrNotRestored`: a DHCP lease since, say). It is idempotent, refuses a plan that does not follow from its `From` (nothing undone), and cannot tell its own change from the same change made since by someone else: it is for a plan whose `Apply` returned nil. A plan that only reloaded cannot be rolled back: its rollback leaves hardn's drop-in, which was there before the plan, and returns `ErrNotRestored`. After Ctrl-C, run it under `context.WithoutCancel` with a timeout ([system.md](system.md) §2.5). Tested: `TestApplyResolved`, `TestApplyFile` (twice each), `TestRollbackLeavesOthers`.
15. **Through `host.System` only.** depguard rule `dns-through-host` denies the package's non-test files `os` (with `os/exec`), `io/ioutil`, `golang.org/x/sys`, `syscall`, `net` (except `net/netip`, which only parses) and `plugin`; `host-stdlib` holds `pkg/host/**` to the standard library and `pkg/host`. Tests run only against `hostfake`.

The `Manager`, `Step` and `FindingKind` words and numbers, and the `EntryKind` numbers a kept plan stores, are stable (`TestCodes` pins every value); none has `MarshalText`, so `p3-output` maps them to its own schema, as for detect's enums ([detect.md](detect.md) §6). A `Plan` survives `encoding/json` but for its `Err` fields, which are not marshalled (`json:"-"`): a plan `PlanDNS` accepted has one only in `UDHCPC.Err` or `UDHCPC.InUseErr`, whose text its `dns-udhcpc` or `dns-udhcpc-unknown` finding keeps, and `Apply` and `Rollback` accept the decoded plan (`TestPlanJSON`, Alpine plans with `UDHCPC.Err` set, with `InUseErr` set, and stopping udhcpc, included). `UDHCPC.InUse` is omitted when Unknown, its zero value, so `pkg/host/revert/plans`' journalled Debian plan (`testdata/dns.json`) is byte for byte as before; a journal written before `next/s2-udhcpc` that stopped udhcpc decodes `InUse` Unknown, and its rollback is refused (`fs.ErrInvalid`: `PlanDNS` now refuses that plan). The journal's format is `p2-revert`'s. `Change.Before` and `After` are for the plan view's diff (`pkg/diff`).
