# DNS resolvers (`pkg/host/dns`)

> **Unit:** refactor plan Phase 2, `next/p2-dns` (brief 2.5 "DNS"; plan row `p2-dns`; findings [§12](../refactor/phase0-findings.md#12-proposed-adjustments-to-the-brief) row 25). V-numbers: V19 (`resolved.conf` overwritten wholesale and systemd-resolved restarted, an empty nameserver list accepted, `lan` forced, NetworkManager not detected, the direct path writing through the `/etc/resolv.conf` symlink; [side-effects.md](../refactor/phase0/side-effects.md) rows 21-23). The DNS screen is slice 2, the pilot of the full flow; this unit is the primitive under it.
> **Status:** built and tested on macOS against the recording fake (`hostfake`) only. `systemctl` and `resolvectl` are modelled by a test handler that follows systemd's sources (§3); nothing was captured from a host. Nothing has run on Linux; §4 lists what is "written, not run (gate 5)". Nothing calls this package yet, so no behaviour changes today.

`dns.Read` establishes what manages `/etc/resolv.conf` and what it holds, `dns.Validate` checks a requested configuration, `dns.PlanDNS` plans the change (pure), and `dns.Apply` runs the plan over `host.System`, backing each file up first, checking that each step took effect and undoing the steps it ran when one fails; `dns.Rollback` undoes a plan.

## 1. Why

origin/main picks one of three strategies and applies it with no validation and no backup: when `systemctl is-active systemd-resolved` succeeds it overwrites `/etc/systemd/resolved.conf` with `DNS=<list>` and `Domains=lan` and restarts the service; when `which resolvconf` succeeds it writes `resolvconf`'s `head` and runs `resolvconf -u`; otherwise it writes `/etc/resolv.conf` in place, through a symlink. An empty list gives `DNS=` or a file with no nameserver (V19; [v032-reference.md](../refactor/phase0/v032-reference.md) §4.5 for v0.3.2, which panicked instead). Brief 2.5 asks to configure the manager when `/etc/resolv.conf` is a symlink; the audit adds that a regular file is not necessarily unmanaged either (findings §12 row 25).

## 2. Guarantees

### Reading (`HostOf`, `Read`)

1. **From detect's facts, never re-detected** ([detect.md](detect.md)). `HostOf` refuses, before anything is read, a distribution not established (`ErrUnknown`, wrapping detect's error), one that is not Debian, Ubuntu, Alpine or Proxmox VE (`ErrUnsupported`), and a container, detected (`ErrContainer`: the container manager provides the file, a decision of this unit) or not established (`ErrUnknown`). It keeps whether systemd booted the host (Unknown when the init system is). Tested: `TestHostOfRefuses` (no call is made).
2. **Reads only.** `Read` makes `Lstat`, `Readlink`, `ReadFileNoFollow`, `Stat`, `ReadDir` and `ReadFile` calls and runs two queries: `systemctl is-active systemd-resolved.service` (on a host systemd booted only) and, for systemd-resolved, `resolvectl --no-pager dns` (with no other argument, which only shows; with arguments it would set). Tested: `TestRead` fails on any other call, for each platform's stock layout.
3. **The manager**, in this order (the order of hex-migration 948b040's detector, plan §6, taken as an idea: a link's target first, then what the file says, then what runs):

   | `/etc/resolv.conf` | systemd-resolved | Manager | hardn |
   |---|---|---|---|
   | link to `/run/systemd/resolve/stub-resolv.conf`, `/run/systemd/resolve/resolv.conf` or `/usr/lib/systemd/resolv.conf` (a relative target is resolved against `/etc`) | any | `systemd-resolved` | writes its drop-in, never the file; refuses when resolved is not running (`ErrNotRunning`) |
   | link to `/run/resolvconf/resolv.conf` | any | `resolvconf` | reports (`ErrManaged`) |
   | link to `/run/NetworkManager/resolv.conf` or `no-stub-resolv.conf` | any | `networkmanager` | reports |
   | link to anything else | any | `foreign` | reports: never written through |
   | regular file whose first line is `# Generated by NetworkManager` / `# Generated by resolvconf` | any | `networkmanager` / `resolvconf` | reports |
   | other regular file, or none | active | `foreign` (resolved reads the file as another package's) | reports |
   | other regular file, or none | not running, or no systemd | `proxmox` on Proxmox VE, else `file` | writes the file |
   | anything else (a directory), or a fact not established | | `unknown` | refuses (`ErrUnknown`) |

   The 948b040 detector also probed `nmcli` and `resolvconf --version`; this one does not, since a tool being installed does not say it writes the file (NetworkManager with `dns=none` leaves it alone, §3). A `systemctl` answer that is not a state systemctl(1) documents (`activating`) is Unknown, never "not running". Tested: `TestReadManagers`.
4. **What the manager holds.** For a file: the address of every `nameserver` line and the last `search` or `domain` line, as glibc reads them (keyword at the start of the line, §3; `ParseResolvConf`). For systemd-resolved: whether `/etc/systemd/resolved.conf.d` is a directory, hardn's drop-in, the drop-ins in any of the four directories that sort after hardn's and assign `DNS=` or `Domains=` (`Later`; hidden files skipped, as systemd skips them), and the global, delegate and per-link servers resolvectl lists, its wrapped lines included. Output in any other form (a colour code, a line it does not print) is Unknown with `detect.ErrUnrecognised`, never an empty list (`TestReadResolvectl`, `TestReadLaterDropIns`). On Alpine: `/etc/udhcpc/udhcpc.conf`, read as plain shell assignments (any other line makes it Unknown, since the script sources it); on Debian and Ubuntu: whether `dhclient` or `dhcpcd` is in `host.SearchPath` (`TestReadUDHCPC`). What could not be read is joined in `State.Err`; udhcpc's own error is kept apart in `UDHCPC.Err`, since it only matters to a plan that changes that file.

### Validation (`Validate`, pure)

5. **No empty list (V19)**: no nameserver is `ErrNoNameservers`. Each entry must be a plain IPv4 or IPv6 address (`net/netip`): a host name, a port, a zone (`fe80::1%eth0`), an IPv4-mapped IPv6 address, the unspecified address and multicast are refused, and so is an address given twice (after canonicalisation: `2001:DB8:0::0053` is `2001:db8::53`). For a file manager, more than three is refused (glibc and musl use the first three and ignore the rest, §3); on systemd-resolved its own stubs `127.0.0.53` and `127.0.0.54` are refused (a loop), where a file may name a local resolver on loopback.
6. **Search domains are kept unless asked.** Without `ReplaceSearch`, the host's search domains are left exactly as they are: the file's `search` and `domain` lines, or the `Domains=` lines of the drop-in hardn wrote before. hardn adds none of its own: origin/main's forced `lan` is gone, and what the DNS screen offers by default is slice 2's decision (plan, slice table: "`lan` default"). With it, each domain must be a host name (labels of letters, digits and hyphens, 1 to 63 bytes, not starting or ending with a hyphen, 253 bytes at most, no trailing dot; systemd-resolved's route-only `~` domains are refused), with no repeat; an empty list removes them. For a file the `search` line must fit musl's 255 bytes (it skips a longer line whole, §3), and on Proxmox VE only one domain is accepted, since its node DNS settings keep only the first (§3). Tested: `TestValidate`.

### Planning (`PlanDNS`, pure)

7. **systemd-resolved: a late drop-in that resets.** hardn writes `/etc/systemd/resolved.conf.d/zz-hardn.conf` (0644, root) and never `/etc/resolv.conf`:

   ```
   # Written by hardn: the system DNS servers for systemd-resolved.
   # An empty assignment resets the list that earlier files built.
   [Resolve]
   DNS=
   DNS=192.0.2.53 2001:db8::53
   Domains=                      (only with ReplaceSearch)
   Domains=example.net           (only with ReplaceSearch and domains)
   ```

   **The plan row's "last file wins" holds for single-value options only.** For a list option such as `DNS=` or `Domains=`, systemd collects the entries of every file in order, and an empty assignment clears what came before (§3). So the drop-in must sort last **and** reset each list it sets; then the main `resolved.conf` and every earlier drop-in can neither add to nor remove from it (`TestApplyResolved` seeds a main file with `DNS=192.0.2.99`, which is gone from the result). Names sort in C byte order across all four directories, and `zz-` sorts after every name that starts with a digit, an upper-case letter or `a` to `y`: after all names in systemd's recommended `60`-`90` range for `/etc`. A drop-in that still sorts later and assigns `DNS=` or `Domains=` (`zz-i…`, `zzz-…`, `~…`) refuses the plan with `ErrOverridden`, naming it: it would add to or reset hardn's list, and the change could not take effect. Anything at hardn's path that is not a regular file (a `/dev/null` mask) is refused too. Then `systemctl try-reload-or-restart systemd-resolved.service`: a reload where the unit supports it (systemd 256 and later: Debian 13, Ubuntu 26.04), a restart where it does not (Debian 12, Ubuntu 24.04), and nothing if resolved stopped meanwhile, which the check after it catches (§3). Per-link servers are reported (item 9).
8. **A file: the nameserver lines are replaced, every other line is kept.** The new `nameserver` lines take the place of the first old one (or are appended), so comments, `options`, `sortlist` and, without `ReplaceSearch`, the `search` and `domain` lines stay where they were; with it, one `search` line takes the place of the first of them. The file keeps its mode and owner; a new one is 0644, root. On Alpine, with `UDHCPCNoResolv` (and only then: an explicit plan step), `RESOLV_CONF="no"` is written to `udhcpc.conf` first, replacing its first `RESOLV_CONF` line and dropping later ones, or appended; the option is refused on any other host (`ErrNotApplicable`). Tested: `TestPlanFile`, `TestPlanFindings`.
9. **Findings** never stop a plan, and say what may undo the change later:

   | Kind | When |
   |---|---|
   | `dns-per-link` | systemd-resolved lists servers for a link or a delegate. **Global `DNS=` does not displace per-link servers** from DHCP, netplan or networkd: resolved queries them in parallel to the global ones (§3). With `/etc/resolv.conf` linked to the uplink file, programs that read it bypass resolved and use its first three servers |
   | `dns-udhcpc` | Alpine, `UDHCPCNoResolv` not asked: udhcpc rewrites the file on each lease (unless `RESOLV_CONF` is `no`, `NO`, empty or another path; `NO_DNS` interfaces excepted), or whether it does is not established |
   | `dns-dhcp-client` | Debian or Ubuntu with a file: `dhclient` or `dhcpcd` is installed, which may rewrite it on a lease **[I]** (findings research §8) |
   | `dns-proxmox-node` | Proxmox VE: the node DNS settings read the file and rewrite it on save, keeping the first search domain and three nameservers |

10. **Refusals**, before anything changes: a manager not established (`ErrUnknown`) or not hardn's to write (`ErrManaged`, naming the manager and the link target or first line), any unread fact (`ErrUnknown`, wrapping why), systemd-resolved not running (`ErrNotRunning`), `ErrOverridden`, and what `Validate` refuses (`TestPlanRefuses`). A configured host plans nothing (`TestPlanFile`'s second plan; the second plan after each `Apply`). Every step is a no-lockout change: no confirm-or-revert timer, and a failure is undone (brief 2.4).

### Applying (`Apply`, `Rollback`)

11. **Before anything changes, `Apply` refuses** a done context, a plan that is not what `PlanDNS` makes from its own `From` and `Want` or whose `From` names a manager its entries do not give (`fs.ErrInvalid`: a journal edited by hand can neither write other bytes nor pick another manager), a plan that writes a file with no `Options.Backups` (`ErrNoBackup`), and a host that differs from `From` in anything a step depends on (`ErrChanged`; `/etc/resolv.conf` turned into a link since the plan is such a change). Then each file the plan writes is backed up through `p2-atomic` (`backup.RollbackRequired`, so even with `enableBackups: false`, §3.16), and the copy must be what `From` read (absent, or the same SHA-256), else `ErrChanged`. Tested: `TestApplyRefuses` (nothing is written outside the backup run).
12. **Each step is checked.** Each file step re-reads its path first and refuses, without acting, one that changed since (`TestApplyChangedDuringRun`), writes with `WriteFileAtomic` (which refuses a symlink, so a link is never written through even if one appears), and reads it back: content, mode and owner. After the reload, resolvectl must list exactly the asked-for nameservers as global ones, in order; a reload that succeeds without that (`DNS=` rejected by resolved's parser, which only logs a warning, §3) is `ErrNotEffective`. The drop-in directory is created (0755) only when it was not there.
13. **Recoverable.** When a step fails, every step that acted, the failed one included, is undone last first under `context.WithoutCancel(ctx)`, bounded by `Options.RestoreTimeout` (`DefaultRestoreTimeout`, two minutes), so a Ctrl-C mid-way still undoes. A file that holds what the step wrote gets its old content, mode and owner back, or is removed when there was none, and the drop-in directory is removed when the plan created it and it is empty; then, when the drop-in was undone, resolved is reloaded and must list the old global servers again. A plan that only reloads (hardn's drop-in already on disk, not yet loaded) has no file to put back and nothing to reload back to, so its reload is not run again. `Result.Done` lists the steps that acted, `Result.Restored` says the undo completed, otherwise the error wraps `ErrNotRestored`; `Result.Backups` names the copies. Tested: `TestApplyFails` (the reload failing, the reload without effect, Ctrl-C during the reload, a write failing, the second of two writes failing), `TestApplyReloadOnly`.
14. **`Rollback(ctx, sys, plan)`** undoes a plan the same way, each step only when its effect is there: a file holding anything other than what the plan wrote is left alone (`ErrChanged`, wrapped in `ErrNotRestored`: a DHCP lease since, say). It is idempotent, refuses a plan that does not follow from its `From` (nothing undone), and cannot tell its own change from the same change made since by someone else: it is for a plan whose `Apply` returned nil. After Ctrl-C, run it under `context.WithoutCancel` with a timeout ([system.md](system.md) §2.5). Tested: `TestApplyResolved`, `TestApplyFile` (twice each), `TestRollbackLeavesOthers`.
15. **Through `host.System` only.** depguard rule `dns-through-host` denies the package's non-test files `os` (with `os/exec`), `io/ioutil`, `golang.org/x/sys`, `syscall`, `net` (except `net/netip`, which only parses) and `plugin`; `host-stdlib` holds `pkg/host/**` to the standard library and `pkg/host`. Tests run only against `hostfake`.

## 4. Written, not run (gate 5)

Nothing here has run on Linux. On the Debian 13, Ubuntu 26.04 and Alpine 3.24 VMs (`next/p2-vmtest`), by hand on Proxmox VE 9, and on a Debian 12 cloud image or Ubuntu 24.04 where one is made:

- `Read` on each stock install gives the manager of the §2.3 table and §3's first row (Ubuntu's stub link with `systemd-resolved` active, Debian 13's regular file with `systemd-resolved.service` inactive or not found, Alpine's file from udhcpc, PVE's static file), with no `Err`;
- the exact text of `systemctl is-active systemd-resolved.service` where it is not installed (Debian 13, `inactive` exit 3 is assumed), and of `resolvectl --no-pager dns` run by `host.Real` (no colour codes, no pager, the wrapping), with and without a DHCP link, on systemd 255 and 259;
- an `Apply` on Ubuntu 26.04 (reload) and Ubuntu 24.04 or Debian 12 (restart): the drop-in in place, `resolvectl dns` listing the new global servers in order, the per-link DHCP server still there (the finding), and name resolution through the stub working; then `Rollback`, with the directory removed and the old servers back. Whether a restart on systemd 252/255 drops queries in flight is not checked;
- that a `DNS=` line resolved rejects (none of hardn's should) leaves the global list unchanged after the reload, so the check catches it;
- on Debian 13: the file rewritten with its comments and options, then whether dhcpcd rewrites it on the next lease (the `dns-dhcp-client` finding);
- on Alpine 3.24: the file rewritten, then a DHCP renewal (`udhcpc` restarted) replacing it without `UDHCPCNoResolv`, and leaving it with `RESOLV_CONF="no"` written; and musl resolving through the three servers;
- on Proxmox VE 9: the GUI's System > DNS showing hardn's servers and search domain, and a save there keeping the other lines;
- in an LXC container on PVE and a Docker container: `ErrContainer`, and that writing the file there would indeed be replaced or refused (the decision's reason, **[unverified]**).

## 5. API

```go
package dns

const ResolvConf = "/etc/resolv.conf"
const DropInDir, DropInName, DropIn = "/etc/systemd/resolved.conf.d", "zz-hardn.conf", DropInDir + "/" + DropInName
const ResolvedUnit = "systemd-resolved.service"
const UDHCPCConf = "/etc/udhcpc/udhcpc.conf"
const MaxNameservers, MaxLine = 3, 255
const DefaultRestoreTimeout = 2 * time.Minute
var DropInDirs []string // the four directories resolved reads drop-ins from

var ErrUnknown, ErrUnsupported, ErrContainer, ErrManaged, ErrNotRunning, ErrOverridden,
	ErrInvalid, ErrNoNameservers, ErrNotApplicable, // the last two wrap ErrInvalid
	ErrNoBackup, ErrChanged, ErrNotEffective, ErrNotRestored error

type Manager uint8     // ManagerUnknown, ManagerFile, ManagerProxmox, ManagerResolved, ManagerResolvconf, ManagerNetworkManager, ManagerForeign
type FindingKind uint8 // FindingPerLink "dns-per-link", FindingDHCPClient, FindingUDHCPC, FindingProxmox "dns-proxmox-node"
type Finding struct { Kind FindingKind; Path, Detail string }
type EntryKind uint8   // EntryUnknown, EntryAbsent, EntryFile, EntrySymlink, EntryOther
type Entry struct { Kind EntryKind; Target string; Data []byte; Mode fs.FileMode; UID, GID int }
type Host struct { Distro detect.Distro; Systemd detect.Tri }
type Link struct { Index int; Name string; Servers []string } // Index 0: a delegate

type Resolved struct { Active, Dir detect.Tri; DropIn Entry; Later, Global []string; Links []Link }
type UDHCPC struct { Conf Entry; Rewrites detect.Tri; NoDNS string; Err error }
type State struct { Host Host; Manager Manager; ResolvConf Entry; Nameservers, Search []string;
	Resolved Resolved; UDHCPC UDHCPC; DHCPClients []string; Err error }
func HostOf(f detect.Facts) (Host, error)
func Read(ctx context.Context, sys host.System, f detect.Facts) (State, error) // reads only
func ParseResolvConf(data []byte) (nameservers, search []string)

type Config struct { Nameservers, Search []string; ReplaceSearch, UDHCPCNoResolv bool }
func Validate(c Config, m Manager) (Config, error) // pure; canonical form

type Step uint8 // StepUDHCPC "udhcpc-no-resolv", StepResolvConf "write-resolv-conf", StepDropIn "write-drop-in", StepReload "reload-resolved"
type Change struct { Step Step; Path string; Before, After []byte; Argv []string; Why string }
type Plan struct { From State; Want Config; Changes []Change; Findings []Finding }
func PlanDNS(s State, c Config) (Plan, error) // pure

type Options struct { Backups *backup.Run; RestoreTimeout time.Duration }
type Result struct { Done []Step; Backups []backup.Result; Restored bool }
func Apply(ctx context.Context, sys host.System, p Plan, opts Options) (Result, error)
func Rollback(ctx context.Context, sys host.System, p Plan) error // after an Apply that returned nil
```

The `Manager`, `Step` and `FindingKind` words and numbers are stable (`TestCodes`); none has `MarshalText`, so `p3-output` maps them to its own schema, as for detect's enums ([detect.md](detect.md) §6). A `Plan` marshalled with `encoding/json` loses its `Err` fields, which a plan that `PlanDNS` accepted has only in `UDHCPC.Err` (a finding's detail); the journal's format is `p2-revert`'s. `Change.Before` and `After` are for the plan view's diff (`pkg/diff`).
