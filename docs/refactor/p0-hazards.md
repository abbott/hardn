# P0.8 hazard gates

> **What this is:** the record of refactor plan P0.8 (`next/p0-hazards`, branched from `next/v0.4` at 5de5406), approved by the maintainer as plan §3.10 on 2026-10-17. Six lockout hazards that Phase 0 verified on origin/main ([phase0-findings.md](phase0-findings.md) §7, [phase0/side-effects.md](phase0/side-effects.md) §8–9) are turned off before Phase 2 starts.
>
> **Gate, not delete:** each old behaviour is still in the code, behind an unexported constant set to `false` whose doc comment begins "DISABLED 2026-10-17. Flip to true to restore." Everything the old path used is kept. Flipping a constant restores origin/main's behaviour, and the goldens named below change back.
>
> **Labels:** V-numbers are the side-effects V-list; A4 is the verification claim behind side-effects §9 D1. File:line references are to the tip of `next/p0-hazards`.
>
> **Status:** written and tested here through the repo's `MockFileSystem`/`MockCommander` seams only. Nothing has run on a Linux host: written, not run (gate 5). No hardn binary was run.

## Still open (not fixed by these gates)

- **No `sshd -t` and no reload:** every SSH write is still followed by a restart (V7); validation and reload are Phase 2 (`p2-sshd-validate`, `p2-reload`).
- **Startup writes:** `main()` still opens `/var/log/hardn.log` and writes `/etc/hardn/hardn.yml.example` before flags are parsed (V26, §3.23), so `hardn -n -d` does that before it is refused.
- **Disable-root edits one file:** on Debian, Ubuntu and Proxmox it edits `hardn.conf`, which `sshd_config` includes first on current releases; an earlier drop-in (V13), a `PermitRootLogin` inside a `Match` block, or an `sshd_config` without the `Include` can still decide the effective value. Phase 2 reads it with `sshd -T`.
- **Proxmox, beyond this gate:** `HardenSystem` stops at the refused UFW step, so with `enableUfwSshPolicy: true` its DNS step does not run (p2-pve is to report `pve-firewall` instead); `ConfigureSSH` still writes the configured `AllowUsers`, which can exclude root and so block cluster root login; the SSH port still changes on Proxmox (V8; PVE needs 22).
- **V24 for `-r` and Run All:** they still write the single default `AuthorizedKeysFile .ssh/authorized_keys`; only `-c` gets the pair.
- **The SSH Login menu's status** reads the files directly and shows `prohibit-password` as "enabled".
