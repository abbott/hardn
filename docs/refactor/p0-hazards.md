# P0.8 hazard gates

> **What this is:** the record of refactor plan P0.8 (`next/p0-hazards`, branched from `next/v0.4` at 5de5406), approved by the maintainer as plan §3.10 on 2026-10-17. Six lockout hazards that Phase 0 verified on origin/main ([phase0-findings.md](phase0-findings.md) §7, [phase0/side-effects.md](phase0/side-effects.md) §8–9) are turned off before Phase 2 starts.
>
> **Gate, not delete:** each old behaviour is still in the code, behind an unexported constant set to `false` whose doc comment opens "`<constant>`: DISABLED 2026-10-17. Flip to true to restore." and then says what the old behaviour does and why it is off. Everything the old path used is kept. Flipping a constant restores origin/main's behaviour, and the goldens named below change back with `-update`: the characterization harness prints each `FIXED` line only when the golden's body shows the fix, and otherwise the `KNOWN-DEFECT` line it replaced (`gateCheck`, `pkg/characterization/operations_test.go`), and a golden holding `FIXED` lines starts "..., with the P0.8 hazard gate(s) below". The one marker it cannot observe is A4's line in `ops/harden_system/*` (with the "after a typed 'yes'" clause of its "Reached by" line), since the Run All screen is `pkg/menu`'s: flipping `runAllWithoutConfirmation` fails `pkg/menu`'s tests, and that line has to be reverted by hand.
>
> **Labels:** V-numbers are the side-effects V-list; A4 is the verification claim behind side-effects §9 D1. File:line references are to the tip of `next/p0-hazards`.
>
> **Status:** written and tested here through the repo's `MockFileSystem`/`MockCommander` seams only. Nothing has run on a Linux host: written, not run (gate 5). No hardn binary was run.

## Tests

All on the mocks; none reads this machine's user, config, OS or `/tmp`.

1. `cmd/hardn`: `TestDryRunRefusesOperations` drives `rootCmd` with every operation under `-n` and `--dry-run`: exit status 2, every operation named, the root check never reached, no call through the provider. `TestOperationsApplyWithoutDryRun` is the control: the same flags without `-n` do write and run commands. `TestDryRunAloneIsNotRefused`. `pkg/cmd`: `TestRefuseDryRunOperations`.
2. `pkg/adapter/secondary`: `TestSetRootLoginFixtures` (Debian 13, Ubuntu 24.04 and Alpine 3.23 style configs in `testdata/sshd_config/` with `Include`, `Match`, commented directives, `PermitRootLogin yes`/`without-password` and `Port 2230`; each edit is idempotent), `TestSetRootLogin`, `TestSetRootLoginRefusesNoUserLeft`, `TestDisableRootSSHInPlace`, `TestDisableRootSSHReadError`. *Since `next/s6-replace`: deleted with gate 2.*
3. `pkg/menu`: `TestRunAllConfirmation` with scripted stdin ("no", empty and "y" cancel with nothing applied; "yes" applies), `TestRunAllConfirmationGolden`.
4. `pkg/cmd`: `TestCreateUserAuthorizedKeysFiles`; `pkg/adapter/secondary`: `TestSaveSSHConfigAuthorizedKeysFile` (also fails if `authorizedKeysFileLinePerPath` is set); `cmd/hardn`: `TestCreateUserAuthorizedKeysFile` (the real `-c` path). *Since `next/s5-replace`: `TestCreateUserAuthorizedKeysFiles` and `TestCreateUserAuthorizedKeysFile` were deleted with origin/main's `-c` path; `TestSaveSSHConfigAuthorizedKeysFile` stays.*
5. `pkg/version`: `TestUpdateCheckDisabled` (every entry point with the network and cache I/O stubbed to fail and record), `TestPlantedCacheIgnored`, `TestUpdateFlagUsage`; `pkg/menu`: `TestStartupMakesNoUpdateCheck` (the start-up update calls against a planted cache); `cmd/hardn`: `TestUpdateFlagsSayDisabled`.
6. `pkg/adapter/secondary`: `TestProxmoxHost`, `TestDisableRootSSHOnProxmox`, `TestSaveSSHConfigOnProxmox`, `TestUFWOnProxmox`; `cmd/hardn`: `TestDisableRootReport`; `pkg/menu`: `TestDisableRootOnProxmoxSaysKeyOnly`, `TestRunAllDryRunOnProxmox` (dry run and live run on Proxmox, Debian as the control); `pkg/characterization`: `TestProxmoxGateThroughSeams` (each operation through the ServiceFactory on hosts found only by `/etc/pve` or by `pve-manager`, plain Debian as the control). *Since `next/s6-replace`: `TestDisableRootSSHOnProxmox`, `TestDisableRootReport`, `TestDisableRootOnProxmoxSaysKeyOnly` and `TestProxmoxGateThroughSeams`' `hardn -d` operation were deleted with `-d`'s legacy path.*

Each gate's test fails if its constant is flipped (checked while building each gate, then restored). With any one constant flipped, or all of them, `go test ./pkg/characterization ./pkg/menu -update` leaves no `FIXED` line naming it apart from A4's (checked in a scratch copy; with all flipped, the ops goldens' markers are next/v0.4's apart from A4's line and V11's lines, which are reworded and, on the Proxmox cells, include the `AllowUsers` defect under "Still open").

## Still open (not fixed by these gates)

- **`-n` in the menus (V2):** gate 1 refuses CLI operation flags under `-n`; it does not make the menus preview-only. `hardn -n` alone opens them in dry-run mode, and the user-management screens still create users, toggle sudo and add keys there, checking `DryRun` only for the success message (`pkg/menu/user_options.go:397`, `:487`, `:538`, `:744`, `:831`; `ssh_keys_options.go:78`). V2 belongs to the user-management slice. *Since `next/s5-replace`: resolved for User Management. Main menu 1 runs the User Management screen on the User control, which stops every change at its plan under plan only; `user_options.go` and `ssh_keys_options.go` were deleted (hard cutover, 2026-11-03).*
- **No `sshd -t` and no reload:** every SSH write is still followed by a restart (V7); validation and reload are Phase 2 (`p2-sshd-validate`, `p2-reload`).
- **Startup writes:** `main()` still opens `/var/log/hardn.log` and writes `/etc/hardn/hardn.yml.example` before flags are parsed (V26, §3.23), so `hardn -n -d` does that before it is refused. *(Since `next/s6-replace`: `-n -d` is no longer refused; it shows the plan.)*
- **Disable-root edits one file:** on Debian, Ubuntu and Proxmox it edits `hardn.conf`, which `sshd_config` includes first on current releases; an earlier drop-in (V13), a `PermitRootLogin` inside a `Match` block, or an `sshd_config` without the `Include` can still decide the effective value. Phase 2 reads it with `sshd -T`. *Since `next/s6-replace`: resolved for `-d` and main menu 2, which read sshd -T and refuse a Match block that lets root in more.*
- **Proxmox, beyond this gate:** `HardenSystem` stops at the refused UFW step, so with `enableUfwSshPolicy: true` its DNS step does not run (p2-pve is to report `pve-firewall` instead); `ConfigureSSH` still writes the configured `AllowUsers`, which can exclude root and so block cluster root login whatever `PermitRootLogin` says (a `KNOWN-DEFECT: V11` line in the Proxmox cells of `harden_system` and `create_user_c_path`; whether `-c`, `-r` and Run All add root there is p2-pve's call) *(Since `next/s5-replace`: the `create_user_c_path` cells were deleted, and `-c` no longer calls `ConfigureSSH`; `-r` and Run All still do)*; the SSH port still changes on Proxmox (V8; PVE needs 22).
- **V24 for `-r` and Run All:** they still write the single default `AuthorizedKeysFile .ssh/authorized_keys`; only `-c` gets the pair.
- **`sshKeyPath` forms (§3.17):** any value not ending in `authorized_keys` is taken as a directory, as v0.3.2 took it, so a per-user file such as `/etc/ssh/authorized_keys/%u`, which origin/main wrote as it is, becomes `/etc/ssh/authorized_keys/%u/authorized_keys` after `-c`. The user screens read that value differently again (they add `.ssh/authorized_keys`).
- **The SSH Login menu's status** reads the files directly and shows `prohibit-password` as "enabled". *Since `next/s6-replace`: resolved; the menu is deleted, and the SSH Login screen reads sshd -T.*
