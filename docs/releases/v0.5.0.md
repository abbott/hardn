# hardn v0.5.0

v0.5.0 installs the vendor's fix for Alpine's sshd password bypass (CVE-2026-123158): hardn upgrades openssh and reloads sshd. Where sshd lacks the fix, the main menu now warns and points to it.

## New: Upgrade openssh (CVE-2026-123158)

- **SSH Login's item 5, Upgrade openssh,** is offered on Alpine where the installed `openssh-server` lacks the fix. It runs `apk update`, upgrades every installed openssh package, reloads sshd, then checks that the package is fixed and sshd runs the new binary. Your SSH session stays open.
- **Run All does it too,** in its SSH Auth row; no hardn.yml key asks for it. Disallow root login, Firewall's Enable and a user's creation refused for the CVE wait until it's done: run Run All again afterwards.
- **Only openssh is upgraded.** If apk would change anything else, such as a library, nothing is upgraded and hardn names it (`ALPINE_NOT_OPENSSH`). Then run `apk -U upgrade`, then `rc-service sshd reload`.
- **There is no undo:** Alpine's repository keeps only the newest package.

See [alpine.md](https://github.com/abbott/hardn/blob/v0.5.0/docs/safety/alpine.md) for the fixed release of each Alpine branch.

## Changed: the CVE-2026-123158 warning

- **The main menu shows a warning** where sshd lacks the fix: "Warning: CVE-2026-123158", "Upgrade openssh.", "Select option: 2) SSH Login". SSH Login shows it too, naming item 5. It replaces SSH Auth's "sshd unpatched: upgrade openssh" and "Anyone can log in: upgrade openssh" on both.
- **An unfixed sshd that no password can reach is now reported too,** with the warning: with password login off, or PAM on, it is `SSH_SSHD_UNFIXED_LATENT`. It adds nothing to the risk score, but keeps the risk level above Minimal.
- **Turning password login on is refused** on an unfixed sshd without PAM (`SSH_PASSWORDS_UNFIXED`).

## Fixed

- **SSH refused on IPv6 alone is no longer a lockout.** Where ufw lets SSH in over IPv4 but not IPv6, the risk level is no longer forced to Critical, the Firewall row no longer says "ssh blocked", and item 1 is Disable firewall, not a refused Repair firewall.
- **Change SSH port refuses a signed number,** such as `+2222`.
