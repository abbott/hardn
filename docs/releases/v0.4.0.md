# hardn v0.4.0

v0.4.0 rebuilds every screen of hardn on one flow: hardn reads the host, shows the plan with its diffs, asks, and only then applies. A change that could lock you out, such as SSH Login's changes or enabling the firewall, asks you to type the hostname, and rolls back by itself unless you confirm it from a new SSH session. hardn now covers an admin user, SSH login, ufw, DNS, automatic updates and backups; it no longer installs packages, Lynis or AppArmor. If you run v0.3.x, read "Upgrading from v0.3.x" first.

## Upgrading from v0.3.x

- **Move hardn's old SSH settings first.** v0.3.x wrote `/etc/ssh/sshd_config.d/manage.conf` (or the `sshConfigFile` your hardn.yml named) and `/etc/systemd/system/ssh.socket.d/listen.conf`; builds of main after v0.3.2 wrote `/etc/ssh/sshd_config.d/hardn.conf`. SSH Login (main menu 2) names them, and refuses its other changes, and `-d`, until they move (`SSH_MIGRATE_FIRST`). Its item 4, Move old settings, moves them into `/etc/ssh/sshd_config.d/00-hardn.conf`: you type the hostname, and the move rolls back unless you run `sudo hardn confirm` from a new session. Logins by keys in v0.3.x's `~/.ssh_<user>` directories keep working. On Alpine, where v0.3.x rewrote `/etc/ssh/sshd_config`, the move puts it back in the shape of Alpine's own file.
- **After the move, change the SSH port by hand.** v0.3.x's `ListenAddress 0.0.0.0:<port>` names the port itself, so SSH Login's Change SSH port is refused (`SSH_PORT_NO_NEW_LISTENER`). Edit that line in `/etc/ssh/sshd_config.d/00-hardn.conf`, run `sudo sshd -t`, then reload sshd, keeping a session open.
- **Ubuntu 26.04: IPv4 SSH comes back.** There, v0.3.x's `listen.conf` leaves SSH on its port listening on IPv6 only, so IPv4 connections are refused. Once the move is confirmed, SSH listens on IPv4 and IPv6 again. Where `listen.conf` never took effect, the move is refused and says what to check first.
- **The main menu is renumbered**: 1 User Management, 2 SSH Login, 3 DNS, 4 Firewall, 5 Backup, 6 Auto Updates, 7 Run All, 8 Environment, 9 System Details, 10 Logs, 0 Exit. Run All moved from 5 to 7, Backup from 10 to 5, Logs from 11 to 10. Dry-Run (6), Linux Packages, Python Packages, Package Sources (7 to 9) and Help (12) are gone.
- **`dryRun: true` in hardn.yml now means a dry run.** v0.3.x ignored it. Check your files: see "Changed: dry run".
- **Scripts and cron jobs: add `--yes`.** Off a terminal, `-c`, `-g`, `-w`, `-d` and `-r` now apply a change only with `--yes`; without it they show the plan and exit 2. A change that could lock you out (from `-w`, `-d` or `-r`) is refused off a terminal, exit status 1, `--yes` or not: run it from a terminal. See "New: `--yes`".
- **Flags removed:** `-l`, `-i`, `-a` and `-s` (the package flags) are now unknown flags, exit status 2.
- **hardn.yml keys:** `disableRoot` is now `disableRootSSH`; the old key still works, with a warning. `logFile` is retired: the log is always `/var/log/hardn.log`. The package lists, repository keys, `dmzSubnet`, the ufw policies, `ufwAllowedPorts`, `enableAppArmor`, `enableLynis`, `sshAllowedUsers`, `sshListenAddress`, `sshKeyPath` and a few more are no longer used: where one is set to other than its default, hardn warns, such as "hardn.yml's enableLynis isn't used". Every older file is still accepted. See "Changed: hardn.yml".
- **No default username.** The example configuration and the first-run question no longer offer `george`. Set `username` in your hardn.yml, or pass `-u`, for `-c` and Run All to create a user.
- **Alpine: install iproute2 before enabling the firewall.** Enabling it (`-w`, main menu 4, Run All) now needs `ss`; without it, it is refused (`FIREWALL_SS_NOT_INSTALLED`), exit status 1. See "Changed: Firewall".
- **Alpine 3.21 is out of scope**: its vendor support ended 2026-11-01. hardn opens its screens there but refuses every change. See "Changed: supported versions".
- **hardn no longer installs packages, Lynis or AppArmor.** What they installed stays installed.

## New: `hardn confirm`, `hardn rollback` and the revert timer

- **A change that could lock you out rolls back by itself** unless it is confirmed in time, such as SSH Login's changes and enabling the firewall. The screen shows when, and how to undo it now.
- **`sudo hardn confirm` keeps it**, from a new SSH connection made from another machine, to the new port where the change added one. The session that made the change, one already open before it, and one through the host itself are refused. At the console it confirms, with a warning that this shows nothing about SSH.
- **`ssh host "sudo hardn confirm"` works** from a new connection, and so does `doas hardn confirm`. While `ssh -L`, `-R` or `-X` is forwarding, a one-command confirm is refused: log in and run it at the prompt.
- **`sudo hardn rollback <id>` undoes it now**: it restores the files the change backed up and undoes its steps. Run again, it finishes a rollback that stopped. `sudo hardn rollback --abandon <id>` gives up a rollback that can never finish.
- **3 minutes, unless `--confirm-timeout` or hardn.yml's `confirmTimeout` says otherwise**: seconds, such as `300`, or a duration, such as `5m`. The flag wins over the file. Less than 60 seconds, or a value that isn't a time, is refused, exit status 2.
- **One change at a time.** While a change waits for confirmation, or a rollback has not finished, the next change is refused, and says how to go on.
- **A reboot doesn't lose the timer.** Before the first such change, hardn installs a boot unit, `hardn-boot` (`/etc/systemd/system/hardn-boot.service`, or `/etc/init.d/hardn-boot` on OpenRC). At boot it restarts the timer for the time left, or rolls the change back before sshd starts once it has run out. It is removed at the first boot with nothing waiting.
- **The next run says what happened**: as root, each command says on stderr that a change is waiting for confirmation, or was rolled back because it was not confirmed. On a doas host these messages say `doas hardn`.
- **Where neither systemd nor OpenRC runs, such a change is refused**, as it is when the hardn binary, or a directory above it, can be changed by a user other than root.
- **Both need root, and `-n` refuses them**, exit status 2. `hardn confirm` exits 1 when it does not confirm.

## New: `--yes`

- **Off a terminal, `-g`, `-c`, `-e` and `setup-sudo-env` apply a change only with `--yes`**, and so do `-w`, `-d` and `-r` for a change that can't lock you out. Without it, the plan is shown, nothing is applied, and hardn exits 2, saying to add `--yes`. A plan with nothing to change exits 0, so a scheduled run on a hardened host is 0.
- **`--yes` never applies a change that could lock you out off a terminal.** Such a plan from `-w`, `-d` or `-r` is refused there, exit status 1: run it from a terminal, where you type the hostname.
- **On a terminal, `--yes` changes nothing.** `-r` asks you to type the hostname whatever the plan; `-w` and `-d` ask for a change that could lock you out; `-c`, `-g`, `-e` and `setup-sudo-env` ask nothing.

## New: the audit log

- **Each change hardn plans is recorded in `/var/log/hardn/audit.jsonl`**: one line per run of an operation flag (`-g`, `-c`, `-d`, `-w`, `-r`, `-e`, `setup-sudo-env`), per change made from a screen, and per `hardn confirm` clean-up. Applied, refused, declined, rolled back, interrupted and dry-run (`-n`, `"mode": "plan"`) runs are all recorded, and so is `-r` refused before it plans (a change waiting for `hardn confirm`).
- **Each line is one JSON document**: the time, hardn's version, the host, the plan with its diffs, what happened and the exit status ([the output reference](https://github.com/abbott/hardn/blob/v0.4.0/docs/reference/output.md)). Read it as root: `sudo tail -n 5 /var/log/hardn/audit.jsonl`, or one record at a time with `jq`.
- **Root's alone**: the directory is `0750`, the file `0600`. Where the directory is not root's alone, or the line can't be written, hardn warns on stderr with the code (such as `AUDIT_DIR_UNSAFE`), and the run and its exit status are unchanged.
- **Not recorded yet:** `hardn confirm`'s confirmation itself, `hardn rollback <id>` (the timer's included), `--abandon` and `--boot`.

## New: Alpine's sshd password bypass (CVE-2026-123158)

- **SSH Auth says when Alpine's sshd lets anyone in.** On Alpine, where sshd checks passwords without PAM and password login is on, hardn reads the openssh package's version and the accounts. An account whose password field is `*` can then be logged in as with any password of 257 to 1024 bytes (`SSH_PASSWORD_BYPASS`, risk level Critical, "password bypass"); an unfixed sshd with no such account yet is `SSH_SSHD_UNFIXED`. Fix it with `apk -U upgrade`, then `rc-service sshd restart` (`apk upgrade openssh` alone leaves `openssh-server` unpatched): hardn reads the package, not the running sshd.
- **Creating a user is refused there** (`USERS_PASSWORD_BYPASS`), from `-c`, Run All and User Management: a new user's field is `*`.

## New: Auto Updates

- **Main menu 6 is Auto Updates.** It shows whether the host updates itself, as apt or apk-cron and crond read it. Opening it changes nothing.
- **Turn automatic updates on**, after showing the change. On Debian and Ubuntu it installs unattended-upgrades where missing and writes hardn's own apt file; on Alpine it installs apk-cron and starts crond.
- **Turn them off where hardn turned them on.** hardn undoes only its own steps. Updates turned on outside hardn are left on.
- **Never on Proxmox VE.** There, 6 only shows the state.
- **hardn keeps a record** of what it turned on, under `/var/lib/hardn/controls/`.
- **Turning updates off saves `enableUnattendedUpgrades: false`** where hardn.yml says true, so Run All doesn't turn them back on.

## New: Environment, `-e` and `setup-sudo-env`

- **Main menu 8, "Keep HARDN_CONFIG"**, keeps `HARDN_CONFIG` under sudo, in hardn's own file, `/etc/sudoers.d/hardn-env-<user>`, so `sudo hardn` reads the hardn.yml you point it at. Once kept, Environment offers to stop keeping it.
- **doas on Alpine.** hardn changes only a doas rule of its own for the user, which this release does not write. Without one, it says to add `setenv { HARDN_CONFIG }` to the rule that lets the user use doas, and changes nothing.
- **A root login is refused**: there is no user to keep it for.
- **The change is backed up first, and rolled back if it fails.**
- **`-e` and `setup-sudo-env` do the same** without asking on a terminal, and off one only with `--yes`. They exit 1 when refused. A change that could lock you out is refused: keep it from main menu 8, which asks you to confirm. With `-n` they show the plan and make no change.
- **`setup-sudo-env` needs root**, as `hardn` does, and reads hardn.yml where there is one, asking nothing where there is none. With none found, `-e` first asks to create one, as `hardn` does at any start.

See [Using with sudo or doas](https://github.com/abbott/hardn/blob/v0.4.0/docs/configuration.md).

## New: System Details

- **Main menu 9, System Details**, shows the OS, kernel, addresses, users, CPU, disk, memory and last logins. It only reads, and opens in a dry run too.
- **`hardn system-details`** prints the same report, needing no root; `> file` saves it. **`--output json`** prints it as hardn's JSON document.
- **A bad combination is refused**, exit status 2: `hardn system-details` with `-p`, `-c`, `-d`, `-g`, `-w`, `-r` or `-e`.

## Changed: the main menu

- **At the top it shows the state** of users, SSH, the firewall, AppArmor and automatic updates, and a risk level. Beside "Select an option" it shows the mode: "Mode Live", or "Mode Dry run" and what set it: "(-n)" or "(hardn.yml)".
- **Every screen is rebuilt, and opening one changes nothing.** Each change is shown as a plan first, then asked.
- **Main menu 2 says "Root login, passwords, port".**
- **The main menu clears the screen only on a terminal.**
- **An invalid choice is answered under the prompt**, which asks again. The screen is no longer cleared, and there is no key press to go on.
- **Going back from a screen clears it**, as opening one does: the main menu is drawn again on a clear screen. Where hardn can read the terminal's height, what the screen printed scrolls into the terminal's scrollback.
- **`sudo hardn` keeps hardn.yml's warnings on screen.** The main menu draws below them.

## Changed: dry run, and `dryRun` is read

- **`dryRun` in hardn.yml is now read.** It was ignored: `hardn` ran live whatever the file said. `dryRun: true` now starts `hardn` as a dry run, as `-n` does: changes are shown, not applied.
- **`-n` and `dryRun` both start a dry run.** A flag given wins: `-n` turns it on, `--dry-run=false` turns it off, whatever the file says.
- **Operation flags show their plan in a dry run**, from `-n` or from the file: `-r`, `-c`, `-d`, `-g`, `-w`, `-e` and `setup-sudo-env` exit 3 when there are changes. Add `--dry-run=false` to apply. `hardn confirm` and `hardn rollback` still run under the file's `dryRun: true`, to keep or undo a change already made.
- **Check older files for `dryRun: true`.** The main menu's Dry-Run item (6) saved it to `./hardn.yml`, as did any menu save made under `-n`. A script or cron job that ran `hardn -r`, `-c`, `-d`, `-g` or `-w` with such a file now shows the plan and exits 3. Set `dryRun: false`, or run with `--dry-run=false`.
- **The menu no longer saves the mode.** Its saves write `dryRun` as the file had it.
- **The main menu's Dry-Run item is removed.** Start with `-n`, or set `dryRun: true`, for a dry run.
- **Run All no longer turns dry run on or off.** It runs in the mode `hardn` started in.
- **In a dry run, every screen opens**, and each change stops at its plan, adding and removing a Firewall profile too, and writes nothing. User Management used to apply its changes even under `-n`.

See ["`dryRun`: dry run"](https://github.com/abbott/hardn/blob/v0.4.0/docs/configuration.md).

## Changed: User Management

- **Main menu 1 is rebuilt.** It shows each user's admin rights (sudo or doas), how they were granted, their SSH keys and their password state. Opening it changes nothing.
- **Each change is shown first.** Grant or remove admin rights, ask or don't ask a password for them, add or remove an SSH key, create a user. A change that could lock you out asks you to type the hostname, and rolls back unless you run `sudo hardn confirm` from a new session.
- **Some changes are refused before anything is asked**, such as removing the admin rights you are using, or your last key.
- **`hardn -c` creates the user**, with admin rights, no password, and every key in hardn.yml's `sshKeys`, without asking on a terminal, and off one only with `--yes`. With `-n` it shows the plan and exits 3. A name already taken, or a key that isn't one, is refused, exit status 1.
- **`-c` no longer changes sshd_config.**
- **`sudoNoPassword: false` warns.** User Management, `-c`, Run All and `-r` don't use it: a new user has no password to ask. hardn warns "hardn.yml's sudoNoPassword: false isn't used".
- **Run All no longer offers to set a username.** With none, it goes on without creating a user.

See ["`username`, `sudoNoPassword` and `sshKeys`: User Management"](https://github.com/abbott/hardn/blob/v0.4.0/docs/configuration.md).

## Changed: SSH Login

- **Main menu 2 is rebuilt.** It shows root login, password login, the SSH port, who is allowed to log in, and how you logged in, as sshd reads them. Opening it changes nothing.
- **Each change is shown first.** Disallow root login or allow it key-only, turn password login off or on, change the SSH port, move hardn's old settings. Each asks you to type the hostname, and rolls back unless you run `sudo hardn confirm` from a new session.
- **hardn keeps its settings in one file**, `/etc/ssh/sshd_config.d/00-hardn.conf`, read before the other drop-ins. See "Upgrading from v0.3.x" for the files earlier versions wrote.
- **Some changes are refused before anything is asked**, such as turning root login off where no other admin could log in by key and become root.
- **`hardn -d` turns root login off the same way.** On a terminal it asks you to type the hostname; off one it is refused, exit status 1: run `hardn -d` from a terminal. With `-n` it shows the plan and exits 3. Root login already off is nothing to change, exit status 0. It is refused where no other admin could log in afterwards, by key, or by password while password login is on, and become root.
- **`hardn -c -d`** creates the user first, then turns root login off only if an admin, the new user among them, can still log in.
- **hardn.yml's SSH settings warn where unused.** SSH Login and `-d` read sshd. `sshPort` is Change SSH port's default, and `sshConfigFile` is read to move hardn's old settings. Where `permitRootLogin`, `sshAllowedUsers`, `sshListenAddress` or `sshKeyPath` is set to other than its default, hardn warns, such as "hardn.yml's sshAllowedUsers isn't used". Run All and `-r` don't read them either; `disableRootSSH: true` is Run All's.

See ["SSH Configuration"](https://github.com/abbott/hardn/blob/v0.4.0/docs/configuration.md).

## Changed: DNS

- **Main menu 3 shows DNS**: what manages `/etc/resolv.conf`, the nameservers and search domains in use, and hardn.yml's nameservers. Opening it changes nothing.
- **Each change is shown first, and asks y/N.** Configure DNS sets hardn.yml's nameservers. Add nameserver, Remove nameserver and the Cloudflare, Google and Quad9 presets change the list, set it, and save the list alone in the hardn.yml hardn loaded.
- **Nameservers are checked.** An address that isn't one, can't be used, or is listed twice is refused; `/etc/resolv.conf` takes three at most.
- **On systemd-resolved, hardn writes its own file**, `/etc/systemd/resolved.conf.d/zz-hardn.conf`. When the reload has no effect, the change rolls back.
- **Where another program manages DNS, hardn only reports it**: NetworkManager, resolvconf, a container, or a link to another program's file. A change there is refused, and says where to set the nameservers.
- **No nameservers is refused.** Configure DNS with none says "Please add nameservers first.", and the last nameserver can't be removed.
- **On Alpine, where udhcpc rewrites `/etc/resolv.conf`**, each change asks whether to stop it.
- **`hardn -g` sets hardn.yml's nameservers the same way**, without asking on a terminal, and off one only with `--yes`. With `-n` it shows the plan and exits 3.
- **A DNS change is backed up, and rolled back if it fails.** It can't lock you out, so there is nothing to confirm.

See ["What Run All reads"](https://github.com/abbott/hardn/blob/v0.4.0/docs/configuration.md).

## Changed: Firewall

- **Main menu 4 shows what ufw does**: whether it is installed and running, its incoming policy, whether it starts at boot, whether SSH gets through, its rules and your application profiles. Opening it changes nothing.
- **Install** installs ufw with apt or apk.
- **Enabling asks you to type the hostname**, and rolls back unless you run `sudo hardn confirm` from a new session. It lets SSH through, denies incoming by default, and starts ufw now and at boot.
- **Disable** turns ufw off, after showing the change.
- **Profiles are applied.** Application Profiles adds a profile to hardn.yml, removes one, and applies them to ufw. Removing a profile leaves its rule in ufw.
- **On Proxmox VE, 4 reads "View pve-firewall"** and only shows pve-firewall. It changes nothing there, and `-w` is refused.
- **`hardn -w` enables the firewall the same way.** On a terminal, a change that could lock you out asks you to type the hostname; off a terminal it is refused, exit status 1: run `hardn -w` from a terminal. A change that can't lock you out is applied without asking on a terminal, and off one only with `--yes`. With `-n` it shows the plan and exits 3.
- **Run All and `-r` enable it the same way.** They no longer set the outgoing policy.
- **Enabling needs `ss`**, from iproute2, to read which ports SSH uses: from main menu 4, `-w`, Run All or `-r`. Stock Alpine lacks it: install iproute2 first, or enabling is refused (`FIREWALL_SS_NOT_INSTALLED`), exit status 1.
- **`ufwDefaultIncomingPolicy` and `ufwDefaultOutgoingPolicy` are not used.** Where hardn.yml sets them, hardn warns, such as "hardn.yml's ufwDefaultIncomingPolicy isn't used".

See ["Firewall Configuration with UFW Application Profiles"](https://github.com/abbott/hardn/blob/v0.4.0/docs/configuration.md).

## Changed: Backup

- **Main menu 5 is Backup.** It shows whether backups are on, the backup path, and past backup runs. Opening it, and Verify Directory, write nothing.
- **Relative paths, and paths under a directory others can change, are refused**, such as `backups` or `/tmp/hardn-backups`.
- **Check `backupPath` in older files.** While it holds such a path, changes from the DNS and Backup screens and `-g` are refused. Change it with Backup's item 2.
- **Turning backups on or off, and changing the path, show the change first.** Only that setting is saved, in the file `hardn` loaded. They used to save the whole configuration to `./hardn.yml`.
- **A path change backs up under the new path**, as does every change after it.
- **Backups off still keeps what a rollback needs.** Changes from the DNS and Backup screens and `-g` still copy the files they change to the backup path, and say so.
- **Backup Runs lists the backups in the path in use**, newest first, and only reads. There is no restore yet.
- **A dropped SSH session during a DNS or Backup change rolls it back**, and `hardn` ends.
- **`-g` interrupted stops the flags after it**, and exits 130 if its change applied.

See ["`enableBackups` and `backupPath`: the Backup screen"](https://github.com/abbott/hardn/blob/v0.4.0/docs/configuration.md).

## Changed: Run All

- **Main menu 7 is Run All, rebuilt.** It shows what Run All would change for each of User, SSH Login, Firewall, DNS and Auto Updates, as hardn.yml asks. Opening it changes nothing.
- **One plan.** Apply all shows every change in one plan and asks you to type the hostname, whatever the plan. A change that could lock you out rolls back unless you run `sudo hardn confirm` from a new session.
- **What it skips, and why.** A change that is refused, doesn't apply, or has nothing to change is skipped, and Run All says why. Root login is turned off only once you log in as the admin, not as root, and not in the same run that enables the firewall: run Run All again. It never changes the SSH port, AppArmor, Lynis or backups, and installs no packages.
- **`hardn -r` runs the same plan.** On a terminal it asks you to type the hostname. Off a terminal a change that could lock you out is refused, exit status 1: run `hardn -r` from a terminal; any other change needs `--yes`. With `-n` it shows the plan and exits 3. `-r` with `-c`, `-d`, `-w`, `-g` or `-e` is refused, exit status 2.
- **`enableUnattendedUpgrades: true` turns updates on**, as Auto Updates does. hardn's first-run question "Enable automatic security updates?" sets it.
- **`ufwAllowedPorts`, `enableAppArmor` and `enableLynis` warn.** Nothing reads them. Where hardn.yml sets one to other than its default, hardn warns, such as "hardn.yml's enableLynis isn't used".

See ["What Run All reads"](https://github.com/abbott/hardn/blob/v0.4.0/docs/configuration.md).

## Changed: Logs and `-p`

- **Main menu 10, Logs, reads the file hardn writes,** `/var/log/hardn.log`, whatever `logFile` says. It only reads, and opens in a dry run too.
- **`hardn -p` alone needs no root,** and off a terminal prints the log's lines and nothing else. To a terminal it prints the file's details and the last lines. With another operation flag it still prints after them.
- **`hardn -p` has exit statuses.** 1 where the log can't be read, with the reason on stderr; 0 with "hardn: no log yet: <path>" on stderr where there is none.

## Changed: start-up and messages

- **hardn writes nothing until it knows what it is asked to do.** `--help`, `--version`, a bad command line and a run as a user other than root write nothing. The main menu, the operation flags and `setup-sudo-env` create `/var/log/hardn.log` and `/etc/hardn/hardn.yml.example` once they run; `confirm` and `rollback` write the log once they are past refusing `-n` and a user other than root. `system-details`, `-p` and a dry run (`-n`) write neither; a dry run is still one line of the audit log.
- **"This script needs to be run as root." comes first.** As a user other than root, hardn says it before anything else; `hardn confirm` and `hardn rollback` say theirs ("must be run as root") first too.
- **Start-up no longer clears the screen**, and no longer prints a line of `~` or "debian trixie detected" ("Proxmox environment detected" on Proxmox VE).
- **Which hardn.yml was read is said once, on stderr**: "Using configuration from: <path>", for `-c`, `-d`, `-g`, `-w`, `-r`, `-e` and `setup-sudo-env`. It is no longer written to `/var/log/hardn.log`. The main menu prints nothing before it starts.
- **The question that creates hardn.yml is asked only on a terminal**, stdin and stdout both. Without one, and at the end of the input (Ctrl-D), no hardn.yml is written and hardn uses the defaults, as when you answer n. Ctrl-C ends hardn (exit status 130) and writes nothing; it does not go on to the operation.
- **No question under `-n`, nor on a system hardn doesn't support.** A dry run reads hardn.yml where there is one and uses the defaults where there isn't. The supported-system check comes before the question. A yes on a live run writes hardn.yml, as asked, even when hardn then refuses the run (such as `-c` with no username).
- **An unsupported OS is still refused**, exit status 1.
- **hardn's messages go to stderr**, in the same look as the screens' messages: errors, warnings and notices, such as "must be run as root" and the reports of `hardn confirm` and `hardn rollback`. They no longer start with "[ERROR]", "[WARNING]", "[INFO]" or "[SUCCESS]". Off a terminal they have no colour codes.
- **Stdout holds a command's output alone.** `/var/log/hardn.log`'s lines are unchanged.
- **A bad command line exits 2 and says so on stderr alone,** for every command: an unknown flag or command, a missing value. It used to repeat it on stdout and exit 1.
- **`hardn --version` prints the version, the commit and the build date.**

## Changed: colour and plain output

- **Screens, plans and messages have a new look**, in colour on a colour terminal, dark by default. `--theme=light` or `HARDN_THEME=light` is for a light terminal; `auto` follows the terminal's background.
- **Off a terminal, output is plain**: no colour or styling, no animation, and ASCII symbols. `--plain` or `HARDN_PLAIN=1` does the same on a terminal.
- **`--color=never` or `NO_COLOR` turns colour off.** `--color=always` keeps it on, off a terminal too; `--color=auto` is the default.
- **ASCII symbols** with `--ascii` or `HARDN_ASCII=1`, `TERM=linux` or `TERM=dumb`, or a locale that isn't UTF-8.

## Changed: hardn.yml

- **`disableRoot` is now `disableRootSSH`.** The old key is still read, as `disableRootSSH`, with a warning that it is deprecated: `disableRoot: true` still has Run All turn root login off. `disableRootSSH` wins where both are set. Rename it in older files.
- **`confirmTimeout`, new**: how long a change that could lock you out waits for `hardn confirm`. See "New: `hardn confirm`".
- **`logFile` is retired.** Where hardn.yml sets it to another path, hardn warns "hardn.yml's logFile, <path>, isn't used". hardn no longer writes the key itself.
- **23 keys nothing reads warn where set**: `dmzSubnet`, the ten package lists, the five repository keys and `alpineTestingRepo`, `useUvPackageManager`, `lang`, `language`, `lcAll`, `tz` and `pythonUnbuffered`. Where one is set to other than its default, hardn warns, such as "hardn.yml's dmzSubnet isn't used". The SSH, firewall, Run All and User Management sections above list the other keys that warn.
- **Every older file is still accepted.**
- **No `george` default.** Neither `hardn.yml.example` nor the copy hardn writes to `/etc/hardn/hardn.yml.example` sets `username: "george"`. The first-run question has no default either: press Enter and no username is saved.

See ["Configuration Options"](https://github.com/abbott/hardn/blob/v0.4.0/docs/configuration.md).

## Changed: supported versions

- **Each version is supported, best effort, or out of scope.** Supported: Debian 13 and 12, Ubuntu 26.04 and 24.04, Alpine 3.24 and 3.23, Proxmox VE 9. Best effort, where hardn changes the host but makes no promises and every plan warns (`PLATFORM_BEST_EFFORT`): Ubuntu 22.04, Alpine 3.22. Out of scope, where hardn shows the screens and refuses every change: Alpine 3.21, Proxmox VE 8, Ubuntu's interim releases, and any version not listed.
- **Alpine 3.21 is out of scope**: its vendor support ended 2026-11-01.
- **Tested on VMs for this release:** Debian 13, Ubuntu 26.04 and Alpine 3.23, including an upgrade from a host v0.3.2 hardened, on Debian 13 and Ubuntu 26.04.

## Changed: install.sh

- **install.sh no longer runs hardn** after installing it. hardn writes `/etc/hardn/hardn.yml.example` itself the first time it runs live.
- **install.sh checks what it installs.** It checks the binary's SHA-256 against the release's `SHA256SUMS`, and its attestation too where gh 2.68.0 or later is installed and signed in; otherwise it says the attestation was not checked and prints the command that checks it. If a check fails, it installs nothing.
- **It refuses armv7**, which has no build, and any other platform without one.
- **It refuses releases without `SHA256SUMS`**: v0.3.2 and earlier. `HARDN_VERSION=0.4.0` pins a version.
- **It installs atomically**: the binary is copied beside `/usr/local/bin/hardn`, checked again, then moved over it. `/usr/local/bin/hardn` as a directory, or a link to one, is refused.
- **These checks take effect once v0.4.0 is out**, when the script on main is updated.

## Changed: the release files

- **Binaries for linux-amd64, linux-arm64 and darwin-amd64**, as before.
- **`SHA256SUMS`, new**, lists each binary's SHA-256.
- **An SBOM** in SPDX JSON, as before.
- **No cosign signatures.** No release had `.sig` or `.crt` files, though the README said its binaries were signed; signing is dropped.
- **SLSA Build Level 3 provenance, as before, now a GitHub artifact attestation** for each binary, in place of v0.3.x's `.intoto.jsonl` files. Check a binary with `gh attestation verify hardn-linux-amd64 --repo abbott/hardn --cert-identity https://github.com/abbott/hardn/.github/workflows/build.yml@refs/tags/v0.4.0 --source-ref refs/tags/v0.4.0 --deny-self-hosted-runners` (gh 2.68.0 or later), or with `verify.sh`, new in the repository, which first checks it against `SHA256SUMS`.

## Changed: building from source

- **Building hardn needs Go 1.26 or later.** Release binaries are built with Go 1.27.3, which `go` fetches by default to build it (go.mod's `toolchain` line).

## Removed: the package flags and items

- **`-l`, `-i`, `-a` and `-s` are removed**: `--install-linux`, `--install-python`, `--install-all` and `--configure-sources`. They installed hardn.yml's Linux and Python package lists, and rewrote `/etc/apt/sources.list` or `/etc/apk/repositories` from its repository keys. Each is now an unknown flag, exit status 2.
- **The main menu's Linux Packages, Python Packages and Package Sources items are gone.**
- **`-c` and `-r` no longer rewrite the package sources, and `-r` no longer installs packages.**

## Removed: Lynis, and setting up AppArmor

- **hardn no longer installs or runs Lynis.** Run All and `-r` did, with `enableLynis: true`.
- **hardn no longer installs AppArmor or puts its profiles in enforce mode.** Run All and `-r` did, with `enableAppArmor: true`. The main menu's AppArmor row only shows its state, read from the kernel; hardn turns it neither on nor off.

## Removed: the main menu's Help item

- **Help (12) is gone.** `hardn --help` gives the flags and commands.

## Fixed

- **`dryRun` in hardn.yml was ignored**; it now means a dry run. See "Changed: dry run".
- **DNS keeps the host's search domains.** hardn no longer writes `domain lan` and `search lan`, and sets every nameserver listed, not only the first two.
- **ufw application profiles' ports** are written joined by `|`, which ufw accepts; they were joined by commas.
- **Ubuntu 26.04: SSH listens on IPv4 again** once v0.3.x's settings are moved. See "Upgrading from v0.3.x".
- **For builds of main after v0.3.2:**
  - `-d` changes root login alone. It no longer rewrites hardn's sshd file from a stub, which reset the port and the allowed users; `hardn -c -d` works again.
  - `permitRootLogin: "prohibit-password"` no longer stops hardn, exit status 2. Like `"yes"`, it warns "hardn.yml's permitRootLogin isn't used".
  - Environment no longer adds `HARDN_CONFIG` to `/etc/sudoers.d/<user>`, which hardn's next sudo change for that user overwrote; a line kept there is read, and left. It no longer writes `Defaults:root` for a root login, or uses `/tmp/hardn_sudoers_temp`. `-e` and `setup-sudo-env` under `-n` no longer make the change.
  - At each start, hardn no longer runs your login shell through `su -` to look for `HARDN_CONFIG`.
  - Opening Backup, and Verify Directory, no longer write and remove `.write_test` in the backup path, deleting a file of that name.
  - Firewall's Install and Disable work; enabling no longer disables and resets ufw first.
  - `hardn system-details` with an operation flag is refused instead of printing the report and not running them. `--json` and `-O json` still work, with a warning to use `--output json`, and `-O text` warns too; `--yaml`, `-O yaml`, `-S` and `-E`, which never did anything, are refused, exit status 2. For `-E`, use `> file`. System Details has no Export item.
  - `--no-color` is now `--color=never`, with a warning that it is deprecated.
  - `--test-update`, `--test-security-update` and `--debug-updates` are removed, as are `HARDN_FORCE_UPDATE` and `HARDN_FORCE_SECURITY`; they did nothing. Each flag is now an unknown flag, exit status 2; the variables are ignored.
  - `hardn --version` prints the commit and the build date again.
