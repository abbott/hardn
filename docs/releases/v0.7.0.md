# hardn v0.7.0

This release supports RHEL 10 and 9, and handles what a stock Alpine container lacks: sshd's host keys and shadow.

## New: RHEL 10 and 9

- **Everything Rocky and Alma Linux have:** users, SSH, firewalld through the Firewall screen, dnf-automatic's security updates, and DNS read only.
- **A dnf install with no enabled repository is refused** (`PACKAGE_NO_REPOS`), as on a RHEL host that isn't registered: register it, or enable a repository. On Rocky and Alma too.

Tested on RHEL 10.3 and 9.9, registered, on x86_64. Not yet on arm64.

## Changed

- **SSH rows say when sshd has no host keys,** as on an Alpine container where sshd was installed but never started: "sshd off, no host keys" in place of "can't read". SSH Login's changes, `-d` and Run All say what to do: make the keys, or, where sshd is off, start it or remove it (`SSHD_ENV_NO_HOSTKEYS`).
- **Enable firewall lists the other ports it will block,** such as a web app's, and how to keep one open (`FIREWALL_PORTS_BLOCKED`). It adds no rule for them. For ufw, and for firewalld on Rocky, Alma and RHEL.
- **The Firewall screen says when hardn runs in a container:** its host may filter traffic too, where hardn can't see it.
- **Create User installs shadow on Alpine** where useradd is missing, after asking. `-c`, `-u` and Run All still refuse, and name doas too when it is missing.
- **The Firewall screen says why a change is refused before asking,** not as Operation Failed after its review. It and Auto Updates say "Checking the host…" while they plan.
- **A change waiting for hardn confirm** is a warning on the Firewall and Auto Updates screens, in SSH Login's words: confirm it from a new connection, or let it roll back.
- **DNS no longer offers to write a resolv.conf that cloud-init wrote:** the DNS row says "cloud-init", on every distribution.

The Alpine changes were tested on an unprivileged Alpine 3.24 container on Proxmox VE, on x86_64.

## Security

- **Built with Go 1.27.4,** which fixes GO-2026-6859 in net/http. v0.6.0 was built with Go 1.27.3.
- **Each binary's attestation bundle is a file of the release,** such as `hardn-linux-amd64.sigstore.json`, so a host with no network can check the binary with gh: see the README's Verify a Release.
- **A release runs CI's checks first,** `make check` and `go test` on each supported distribution, and builds nothing if one fails.
