# hardn (next release)

> **Draft: every line is proposed until the maintainer approves the words.** At the release candidate this file becomes `docs/releases/v<x.y.z>.md`, the release's whole body, and this note is cut.

## New

- **The main menu warns when a release's vendor support ends within 90 days, or has ended**, and names the release to upgrade to. Every plan carries the same warning (`PLATFORM_SUPPORT_ENDS`, `PLATFORM_SUPPORT_ENDED`). It changes nothing hardn does. Proxmox VE 9 has no date yet, so no warning. The dates are in docs/platforms.md.
- **The JSON document has `host.platform.supportEnds`**, the date hardn holds for the release.
- **hardn can tell you when a newer release is out.** Set `checkReleases: true` in hardn.yml, and the main menu says so under the repository link, such as "v0.9.1 available". As root, `hardn --version` says it too, from the last check. It is off by default. On, hardn asks GitHub for the latest release's tag at most once a day and sends nothing about the host. See [docs/configuration.md](../configuration.md).
- **verify.sh, and install.sh given `HARDN_VERSION`, say when a newer release is out.** They ask GitHub once, as their last step.
- **`hardn --version` has a `Repo` line.**
- **Firewall shows each listening port against the rules**: open, let in from some sources, blocked, or local only, with the program. A port the rules let in with nothing listening is flagged. It changes nothing.
- **System Details lists the listening ports**, and `hardn system-details` prints them. Run it as root to see every program. `--output json` doesn't include them.
- **SSH Login shows sshd's own brute-force limit.** The row "Brute-Force Limit" reads On, Off (with the file that turns it off) or "Not available" on an sshd before OpenSSH 9.8. It changes nothing.
- **Firewall can limit repeated SSH connections (item 5, Limit SSH).** On an active ufw that allows SSH from anywhere, it turns that rule into ufw's limit: an address that opens 6 or more connections in 30 seconds is refused, yours included. `ufw allow <port>/tcp` undoes it. Not on Rocky, Alma, RHEL, CentOS Stream or Oracle, and not part of Run All.
- **User Management has an Account Review (item 3).** It lists accounts with an empty password, a password that never expires, or no login in 90 days, each with the command to run. It changes nothing.
- **An empty password shows on the main menu** as "Empty password" under User, and lowers the security level. Its finding code is `USERS_EMPTY_PASSWORD`.
- **SSH Login lists every SSH key sshd reads, by account (item 6, SSH keys).** It marks a weak key (DSA, or RSA under 2048 bits), a key more than one account holds, and a key this sshd refuses. A key file it can't read, and lines that are no key, are shown as such. It changes nothing.
- **`hardn system-details --output markdown` prints a report to hand over**, for an auditor or a manager: the host and its support level, the risk level and why, each control's status with its evidence, the findings, and System Details. It is one Markdown document on stdout: save it with `> web-01.md`. It changes nothing and exits 0. Run it with `sudo` or `doas`: without root, what only root can read shows Unknown, and the report says so. Unlike the other forms of `system-details`, it reads hardn.yml, for the DNS row.
- **`hardn check` tells you when a host has changed.** `sudo hardn check --accept` saves the host as the baseline: who can become root and their SSH keys, sshd's logins and port, the firewall and its rules, the listening ports it lets in, the nameservers, automatic updates and the syslog servers. `sudo hardn check` compares, with one line for each difference, and exits 3 when there is one, for cron and CI. `--output json` prints it as JSON. After hardn applies a change, its result says to accept again. See [docs/usage.md](../usage.md#hardn-check).
- **The audit log records confirmations and rollbacks.** Each `hardn confirm` and `hardn rollback` (`<id>`, `--abandon`, `--boot`) adds a line to `/var/log/hardn/audit.jsonl` with who ran it, the change's id and how it ended, refused and failed runs included. The rollback of a change nobody confirmed is recorded too. See [output.md](../reference/output.md) §4.1.
- **install.sh and verify.sh mark each step**: downloaded, SHA-256 matches, provenance verified or not checked, with a warning where provenance isn't checked and one closing line that says what was installed or verified. Colour shows only on a terminal, and not with `NO_COLOR`; the words are the same without it.
- **NTP Settings (main menu 8, Configuration, then 3) shows the host's time service and clock, and sets your time servers.** Name one to four in hardn.yml's new `ntpServers`. Set servers makes chrony, systemd-timesyncd or Alpine's busybox ntpd use them in place of its own; Remove servers puts those back, each file as it was. hardn installs and starts no time service. Servers set outside hardn are shown, never changed. Run All sets the servers too. The main menu shows an NTP row on every host but a container; it never changes the risk level. System Details and the Markdown report show the time service and the clock, and the JSON document has `details.time`. New error codes: `NTP_*`. What is written on each distribution: [docs/platforms.md](../platforms.md#ntp).
- **Syslog Settings (main menu 8, Configuration, then 2) sends the host's logs to one to four syslog servers.** Name them in hardn.yml's new `syslogServers`, a list (each `server`, `port`, `protocol`: udp, tcp or tls, `caFile`). Set servers writes hardn's own rsyslog file, checks it, restarts rsyslog and logs a test line; each server has its own queue, so that one that is away does not hold up the others; on a host with journald alone it installs rsyslog (not on Proxmox); on Alpine it sets busybox syslogd's `-R`, UDP only. Stop forwarding undoes only what hardn set. A list hardn can't set whole is refused. Servers set outside hardn are shown, never changed. Run All sets the servers too. The main menu shows a Syslog row where a server is named or the host forwards; it never changes the risk level. New error codes: `SYSLOG_*`.
- **CentOS Stream 10 and 9 and Oracle Linux 10 and 9 are supported**, as Rocky, Alma and RHEL are.
- **Kernel Settings (main menu 8, Configuration, then 4) shows 19 kernel settings (sysctl) against a baseline, and sets the ones below it.** Apply settings writes them to `/etc/sysctl.d/90-hardn.conf` and sets them at once; Remove settings puts the earlier values back. A stricter value is never lowered, forwarding is never changed, and a host that routes keeps Sending redirects and Reverse-path filter as they are. `kernel: true` in hardn.yml adds it to Run All and the main menu. New error codes: `KERNEL_*`.

## Changed

- **hardn rotates its own logs.** Over 10 MiB, `/var/log/hardn.log` becomes `hardn.log.1` and a new file starts; four older copies are kept. `/var/log/hardn/audit.jsonl` does the same over 5 MiB, with nine. Logs and `hardn -p` to a terminal show the current file and name the older copy.
- **Configuration (main menu 8) is now a menu**: 1 hardn.yml, the screen it opened before, 2 Syslog Settings, 3 NTP Settings, 4 Kernel Settings. The main menu's keys are the same, and `hardn config` prints hardn.yml as before.
