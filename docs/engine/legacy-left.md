## 2. Re-home order

Each step builds and passes `make check` alone.

1. **`pkg/cmd`.** `SystemDetailsCmd` and its form to `cmd/hardn`; `ExitUsage` to `pkg/output`, beside the codes its test checks. Delete `pkg/cmd`.
2. **The status block and the factories** (decisions 1 and 2, (a) each). Delete `legacySecurityStatus` and what only it reaches (decision 1's list), `pkg/security` whole; `menu.NewMainMenu(cfg, versionService)`, with no `MenuManager` or `OSInfo`; `main.go` drops `provider`, `serviceFactory` and `menuFactory`. Delete `pkg/infrastructure`, `pkg/application`, `pkg/domain`, `pkg/adapter`, `pkg/port`, `pkg/interfaces` (its `mock_interfaces.go` too: a non-test file only tests use). In `pkg/characterization`, delete the `host_info` test and `testdata/golden/host_info/debian.golden`, and delete or re-seat on `host.System` the harness's recorders over `pkg/interfaces` (`harness_test.go:135,171`), which the backup and config-load goldens also use.

4. **The clear.** A clear in `pkg/ui/term`, a no-op when `Plain`; `showScreen` and `ShowMainMenu` call it.
5. **Start-up** (decision 4). The refusal of an unsupported OS from `pkg/host/detect`, exit 1 as now; `FindConfigFile` returns what it found and `cmd/hardn` says it; `initializeColor` keeps `color.NoColor` alone. Delete `pkg/osdetect`, `pkg/utils`, `pkg/style` (`pkg/menu`'s tests take `ansi.Strip` from `charmbracelet/x/ansi`, a direct dependency, for `style.StripAnsi`).
6. **`pkg/logging`** (decision 5). The file writer in `pkg/output`, the line format byte for byte, so `logview` and its tests hold; `revertFileLog` and `engine.go`'s file-only lines onto it; the console lines onto `component.Messages`; `setRevertColour` (`output.go:220`) and `FallbackOutput` go. 7. **`pkg/menu`** into `pkg/screens/mainmenu` (`Run`, the items as one list with the gallery's fixture, item 2's words per decision 7). `hooks.go` builds `Options`. Delete `pkg/menu`.
8. **`pkg/config`'s retired keys.** Remove the `Config` fields themselves, and `retired.go` with them; a file that sets one still gets "isn't used". With decision 6 (a), the prohibit-password refusal goes here too.

## 3. Decisions for the maintainer

**1. The status block switch, `legacySecurityStatus`. GATES step 2.** The maintainer made the main menu live on 2026-10-23 (slice 2) and kept origin/main's status block behind this false constant (`pkg/menu/main_menu.go:119`) as a restore switch. While it is false nothing draws the block; it is the last reader of `MenuManager`, the host-info chain and `pkg/security`.
- **(a), recommended:** delete the switch and everything only it reaches: `showLegacyStatus`, `displaySecurityStatus`, `displayNormalSecurityStatus`, `formatOSTitle`, `formatHardnVersionLine`, `formatHostInfoLines`, `pkg/security` whole, `MenuManager`'s and `HostInfoManager`'s `GetHostInfo`, `FormatUptime`, `FormatBytes` and the host-info chain, the `pkg/style`, `pkg/utils` and `pkg/osdetect` code only they use (`osdetect.NewRealFileSystem`, `NewRealCommander`), and `pkg/characterization`'s `host_info` test. The hard cutover (maintainer, 2026-11-03: legacy code is deleted, never frozen) and the plan's rule that this unit removes whatever legacy code is left.
- **(b):** keep the switch, and with it every package step 2 deletes.
- **Changes:** nothing a user sees either way while it is false.

**2. `legacyThroughHost` and P-32. GATES step 2.** `pkg/interfaces/system_adapter.go:24` is a false switch that would route the legacy `OSCommander` and `OSFileSystem` through `host.Real` (`SystemCommander`, `SystemFileSystem`, `realSystem`, `legacyError`), built for P-32 (`docs/refactor/proposals.md`, still "proposed"), which asked to run origin/main's commands through `host.Real`. Those commands are deleted; P-32 has nothing left to route.
- **(a), recommended:** P-32 withdrawn; the switch and its adapters deleted with `pkg/interfaces` in step 2.
- **(b):** keep P-32 open, and `pkg/interfaces` with it.
- **Changes:** nothing a user sees.

**3. The update-check flags and the security-update alert. GATES step 3.** `--test-update`, `--test-security-update`, `--debug-updates` and `HARDN_FORCE_UPDATE`, `HARDN_FORCE_SECURITY` are accepted and do nothing since update checks were disabled (2026-10-17, `pkg/version/checker.go:44`); their help says so. The only code that would draw an update, the version line's "available" and the security alert that replaces the menu (`displaySecurityUpdateAlert`, `main_menu.go:516`, called from `ShowMainMenu` at 759), is pkg/menu's, in `pkg/style`, off.
- **(a), recommended:** remove the three flags, the two variables and pkg/menu's alert drawing (`displaySecurityUpdateAlert` and its call in `ShowMainMenu`); `pkg/version`'s checker and its `updateCheckEnabled` switch stay for P-15, the update checker made opt-in, which draws a notice on the new header when checks return. Nothing reachable is lost.
- **(b):** keep them, inert, until P-15; their fields move to `pkg/screens/mainmenu` with no renderer.
- **Changes:** (a) takes three lines out of `hardn --help`, and `hardn --test-update` becomes "unknown flag", exit 2.

**4. Start-up's lines and clears. GATES step 5.** Every `hardn -c`, `-d`, `-w`, `-g`, `-r`, `-e` and the main menu's start begin with origin/main's start-up: which `hardn.yml` was read, a screen clear, a green `~` line, "debian trixie detected" and on a PVE host "Proxmox environment detected", in colour codes and with the clear even when stdout is a pipe or a file (§1, written by `pkg/config/config.go:225-284`, `pkg/osdetect/osdetect.go`, `pkg/utils/utils.go:9-25`). On a terminal the clear erases the config line and the scrollback above the command; off one the codes are noise in a log, against the design system's plain output off a terminal.
- **(a), recommended:** drop the clear, the `~` line and both "detected" lines; say which `hardn.yml` was read in one plain line on stderr for the flags and the `setup-sudo-env` subcommand, and nothing before the main menu, which clears over it; the main menu clears only on a terminal; an unsupported OS still refused, exit 1. The config path is the one fact here shown nowhere else (`-f`, `HARDN_CONFIG` and the search path pick it); the OS is on the main menu's context bar.
- **(b):** drop all of it, the config line too. Quietest; which file was read is then unsaid.
- **(c):** keep every line on a terminal; off one write them without colour and without the clear.
- **Changes:** a flag's output starts with its plan; slice 8's VM transcript of `hardn -r`; the clear counts in `pkg/menu`'s tests. The first-run offer to create `hardn.yml` is unchanged.

**5. The form of hardn's console lines. GATES step 6.** Every console line hardn prints outside the screens (the root check's "[ERROR] This script needs to be run as root.", `hardn confirm`'s and `hardn rollback`'s reports, `-r`'s errors, the config line) print as "[ERROR] …", "[WARNING] …", "[INFO] …", "[SUCCESS] …" on stdout through `pkg/logging`, coloured unless `--no-color` (confirm and rollback only on a colour terminal, `output.go:220`). The new design's failures already render otherwise: off a terminal `-g`'s reads "# Operation Failed", the message, the code.
- **(a), recommended:** every console line a `component.Message` on stderr, its kind's look, plain off a terminal. One look across hardn, and stdout holds a command's output alone, defect 28's rule.
- **(b):** keep the "[ERROR]" words; move them to stderr; colour only on a colour terminal.
- **(c):** keep them as they are, `pkg/logging`'s console half kept in the new design.
- **Changes:** the strings asserted in `cmd/hardn/confirm_test.go`, `revert_test.go`, `revert_boot_test.go`; the journal lines of confirm and rollback under the systemd timer. `/var/log/hardn.log` is unchanged either way.

**6. `permitRootLogin: "prohibit-password"` refused at load. GATES the refusal's removal in step 8.** `pkg/config/rootlogin.go:71`, `prohibitPasswordApplied`, DISABLED 2026-10-17, makes `checkLoaded` (82) refuse that value with `ErrRootLoginNotApplied` (75), exit 2 (`pkg/output/codes.go:205`): origin/main's SSH writers would have written "PermitRootLogin no" for it. Those writers are gone and nothing reads `permitRootLogin` now; it is warned "isn't used". Today a `hardn.yml` with prohibit-password stops hardn, exit 2.
- **(a), recommended:** drop the refusal, its error and its code, so the value only warns as unused, as "yes" does ("no", the default, warns nothing; `output.go:177`). A refusal guarding a writer that no longer exists stops a user for nothing.
- **(b):** keep refusing.
- **Changes:** with (a) a host whose `hardn.yml` says prohibit-password runs, with "hardn.yml's permitRootLogin isn't used", where it now stops with the refusal and exit 2.

**7. Main menu item 2's description** (P-07 (a); `pkg/menu/main_menu.go:857`, `pkg/ui/screen/fixture.go:65`). It says "Toggle SSH root access"; since slice 6 the SSH Login screen disallows or allows root login, turns password login on or off and changes the port, each item named by its result (P-12).
- **(a), recommended:** "Root login, passwords, port": the three things the screen changes, as item 1's "Create, Configure" names its two.
- **(b):** "Configure SSH login", as items 3, 4 and 6 say "Configure"; it says less.
- **(c):** keep it; it names one of three and a toggle the screen no longer has.
- **Changes:** `pkg/menu/testdata/golden/main_menu_live`, `pkg/ui/screen/testdata/golden/main-menu`, `internal/tools/uigallery/testdata/golden/status` and `play`. Gates nothing; lands with step 7 at the latest.
