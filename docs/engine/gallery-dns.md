## 4. Decisions for the maintainer

Adopted by the maintainer on 2026-10-22 ("those all seem okay to adopt"): each recommendation below, with the recommended answers to 1 (i) to (iii); decision 8 is the design of the DNS row for its unit, P-01 itself still proposed. The alternatives stay recorded. The words in §5 not named by a decision stay proposed.

1. **Edits go through the plan.** Add nameserver, Remove nameserver and the presets plan the list they make, the host's change and the save of hardn.yml, which runs only after the change applies; n changes and saves nothing. *Recommended:* this, which fixes "presets don't apply" and gives each change a review. *Alternatives:* (a) origin/main's: Add, Remove and the presets change hardn.yml alone (now at its loaded path, §3.19), and only Configure DNS applies, through the plan; (b) as recommended, but saving hardn.yml before the apply, so that a failed apply still records the list; (c) a question after a successful apply, "Save to hardn.yml?", so that a host can be changed without changing the configuration. *Consequences of the recommendation:*
   - (i) origin/main's descriptions of Add and Remove, "Add a new DNS server to configuration" and "Remove a DNS server from configuration", now understate the action, which applies to the host too; the presets' "Set nameservers to ..." reads true. The mock keeps origin/main's words; proposed alternatives: "Add a DNS server and apply it", "Remove a DNS server and apply the rest". Not mocked.
   - (ii) The last nameserver cannot be removed: `dns.PlanDNS` refuses an empty list (`DNS_NO_NAMESERVERS`), so with one configured item 3 refuses before it asks, "The last nameserver cannot be removed." (proposed; mocked, sequence 13). Alternatives: Remove changes hardn.yml alone when it would leave none, applying nothing, as origin/main's Remove did; or item 3 not shown with one, as with none.
   - (iii) A save that fails after the change applied. *Recommended:* the change rolled back, as the engine rolls back every change before a failed step, so that the host and hardn.yml still agree (what `-fail 2` shows, by the gallery's convention, §3). *Alternative:* the host's change kept, and the report saying that hardn.yml was not saved. Not mocked as a sequence of its own.
   - *Amended by the maintainer on 2026-10-22, for every slice (refactor plan §3.19):* "Change the hardn.yml save to edit only the keys that changed, keeping the rest of the file and its comments, for every slice; drop the comments-lost warning." The save is still planned, run and rolled back as above; it now edits the settings that changed in place, and the review's last warning line, "Saving hardn.yml loses its comments", is gone from the mocks (built by `next/s2-config-edit`, [config-edit.md](config-edit.md)).
2. **The search domain** (the plan's "`lan` default"). *Recommended:* hardn keeps the host's search domains (`pkg/host/dns`'s default, `ReplaceSearch` false), the screen shows them, and no configuration key is added: origin/main forced `domain lan`/`search lan` on every apply (V19). On systemd-resolved the row shows each link's domains after the global ones, with the link, as the Nameservers row shows its servers: "example.net (eth0)". That reading is not `dns.Read`'s: it keeps resolved's global search domains alone and drops each link's (§8), so unit (b) adds them to `dns.Resolved`, or the row says Unknown on resolved. *Alternatives:* (a) a "Search domain" field, default "lan", for parity with origin/main: a new configuration key (a surface change, plan §3.11's kind), and on Proxmox VE one domain only (`dns.Validate`); (b) show nothing about search domains, as origin/main did; (c) on systemd-resolved, Unknown, or the global ones alone, labelled so, until `dns.Read` keeps the links' domains. Not mocked.
3. **P-30, the empty list.** *Recommended:* (b), mocked: a bullet item of the section, origin/main's words, "- No nameservers configured", muted, the dash lines' `text.muted` for what is not a warning (`ValueNone`, DEV-061); no layout change. *Alternatives:* (b) in Figma's checklist colours, the dash muted and the words in `text.primary`, which needs no component state (as the first mock drew it); P-30 (a), a notice block (a warning `Message`) in the sub-menu layout; (c) a status row. Configure DNS then refuses with origin/main's "Please add nameservers first.", its first sentence, which the item already says, left out.

The review is built before the plan, from `dns.State.Findings()`, which is pure, less `dns-udhcpc` on `/etc/udhcpc/udhcpc.conf` when the RESOLV_CONF question is answered y, as `dns.PlanDNS` filters them (its `Plan.Findings`, which the mock shows): no flow change is needed. 1. **`steps.DNS` does not copy `dns.Plan.Findings` onto `engine.Change.Findings`.** On Ubuntu 26.04 with a DHCP link, `PlanDNS` gives one finding (`dns-per-link`), the change none, and `output.AfterFlow` then writes nothing: the real flow shows no DNS finding anywhere today.
2. **A created file's diff is taken against "", not `/dev/null`.** For the drop-in, `steps.DNS`'s diff starts `--- /etc/systemd/resolved.conf.d/zz-hardn.conf` where `engine.FileDiff(path, nil, ...)` gives `--- /dev/null`, so `--output json` and any reader of the diff see an empty file edited, not a file created. `PlanView` draws both alike (it leaves out the pair when one names the target), so the screen does not show it; `TestDNSPlansAreReal` allows only that difference.
3. **The failure names nothing rolled back.** When the reload has no effect, `dns.Apply` undoes its own steps (the drop-in removed, the old servers checked), `steps.DNS` then drops its journal step (`unitRan`), and the engine's rollback has nothing to undo, so it reports no change rolled back: the user reads "Operation Failed" and never that the change was undone. Proposed for unit (b), and mocked as `failure-proposed`: report the change rolled back when the unit's own undo finished (`dns.Result.Restored`), as the engine does for a journalled step, and word the report. The report's words today are `pkg/host/dns`'s error, with its Go quoting (`[]`, `["192.0.2.54" ...]`) and the code twice.
4. **`dns.Read` drops each link's search domains.** It reads `resolvectl --no-pager domain` and keeps the global list alone (`read.go`: `r.Domains, _, err = resolvectl(ctx, sys, "domain")`), where it keeps each link's servers (`Resolved.Links`). On the Ubuntu host, whose eth0 has example.net from DHCP, `dns.Read` gives no search domain at all (`Resolved.Domains` and `State.Search` empty), though the drop-in sets no `Domains=` and eth0's stays in use. Proposed for unit (b): keep the links' domains beside their servers, so that the screen's row is `dns.Read`'s (decision 2).
