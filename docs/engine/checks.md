# Check-only controls: the status model's pattern (`pkg/engine/controls/<area>`)

> **Unit:** refactor plan Phase 4, `next/p4-check-ssh` (plan §2, rows `p4-check-<area>`: "Check-only Controls: `Check` implemented, `Plan` returns `ErrNotMigrated`"; brief Phase 4, "Status model and live main menu"; brief §3 principles 1 and 3). The first Phase 4 unit sets the pattern on this page; its own controls are on [check-ssh.md](check-ssh.md). The other `p4-check-<area>` units (firewall, users, apparmor, updates) follow it and add their own pages.
> **Status:** the pattern is built and tested with the SSH controls, on macOS, against the recording fake (`hostfake`) only. Nothing has run on Linux.

Phase 4 gives the main menu's status rows a source: one engine `Control` per row, whose `Check` reads the host and whose `Plan` waits for the slice that migrates the area. Until then the control is **check-only**: it reports the host's state and plans nothing.

## 1. The pattern

1. **A check-only control** is an `engine.Control` (engine.md §2.1) that implements `ID`, `Title`, `Applies` and `Check`, and embeds `engine.CheckOnly`, whose `Plan` returns **`engine.ErrNotMigrated`** and changes nothing. `Engine.Plan` treats that as any control's error: the plan is refused, the item's error is `ErrNotMigrated` (code `CONTROL_NOT_MIGRATED`, exit 1), and nothing is applied. A plan cannot claim to bring a host to a state one of its controls cannot plan. The slice that migrates the area replaces the embedded `Plan` with its own.
2. **One package per area**, `pkg/engine/controls/<area>`: `ssh` first, then `firewall`, `users`, `apparmor` and `updates`. Each exports its controls as types and `Controls() []engine.Control` in Figma's row order. A control's `ID` is `<area>.<row>` (`ssh.login`), stable once released; its `Title` is Figma's row label (`SSH Login`).
3. **What `Configured` means for a check-only control:** the host as hardn's baseline wants it, which is the brief's for each source (brief Phase 4, "Where each status comes from"; brief 2.5 per distribution) with Figma's details as the anchor ("root disallowed", "key-only auth", "non-default (2230)"). A check-only control reads no configuration, since `Check` takes none (engine.md §2.1): what `hardn.yml` asks for is the slices' to compare. `Partial` is some of it; `NotConfigured` none of it, or the opposite.
4. **The host's actual state, not the files** (brief §3 principle 3): each check reads through the Phase 2 readers ([docs/safety/README.md](../safety/README.md), "Status sources"), never a configuration file on its own, and only through `host.System`.
5. **`Unknown` rather than a guess** (brief Phase 4). Two kinds:
   - **a read that fails** (a command that cannot run, a file that cannot be read, `sshd -T` refusing the configuration): `Check` returns `Status{State: Unknown, Detail: …}` **and the error**. `Engine.Check` reports it `Unknown` with the error (engine.md §2.1), the document puts the error in `errors[]` with its registered code, and the run exits 1, as a failed check does (output.md §2.8). The detail says what the error shows of the host where it does ("sshd not running"), else "can't read";
   - **what was read but does not establish the state** (a value in a form hardn does not know, two sources that disagree, the unit that listens not up): `Unknown` with no error and with the findings that say why. A check exits 3 then, as for any state but `Configured` and `NotApplicable`: a state not established is not taken as hardened (output.md §2.8).

   A state that is established is reported even when something else is not (a password login allowed is `NotConfigured` whatever keyboard-interactive says). `Unknown` counts as not configured and adds a factor (plan row `p4-risk`).
6. **`NotApplicable` only through `Applies`**, with the reason as its detail (engine.md §2.1): a control that does not apply to the host is neither checked nor planned. A control applies unless detect's facts *establish* that it does not (AppArmor inside a container, brief 2.5); a fact detect could not establish is not grounds for `NotApplicable`, which leaves the row out of the risk level.
7. **Findings** explain a state; they never set it. Each has a stable SCREAMING_SNAKE `Code` registered in `pkg/output`'s registry (appended, its golden list regenerated with `make golden-update`, a row in [docs/reference/output.md](../reference/output.md) §2.2), a one-line `Detail` and a `Source` (`file:line`, or the command). A primitive's finding keeps its kind's code under the primitive's prefix, derived as `pkg/engine/steps` derives it (`SSHD_SHADOWED`, `PVE_PORT_NOT_22`; steps.md §2.23). An area's own codes are exported constants of its package, added to `TestFindingCodes`' list.
8. **Evidence** lists what each state was read from, one line per source, as the command printed it: `sshd -T: permitrootlogin no`, `systemctl show -p Listen ssh.socket: [::]:2230`, `ss -Htln: *:2230`.
9. **Words.** A detail is as short as it can be, in the user's terms, lower case like Figma's, describing the host and never hardn, never repeating the row's label or state word (design-system README §9.15). The room beside the label at 64 columns is 26 cells after "Configured", 22 after "Not Configured" or "Not Applicable", and 29 after "Partial" or "Unknown" (design-system README §9.3); a longer detail is cut with the ellipsis.
10. **Every status line in a table.** Each area's page lists every line its controls can show (the host's state, then `State` and the exact `Detail`), every `Unknown` included, as [P-43](../refactor/proposals.md#p-43) (3) does for AppArmor. Wording is the maintainer's decision: new wording is marked *proposed* until it is approved.
11. **Read-only, through `host.System`.** depguard rule `controls-through-host` (the last of the rules) denies `os`, `io/ioutil`, `golang.org/x/sys`, `syscall`, `net` (but `net/netip`), `plugin`, `pkg/ui` and `pkg/output` to the non-test files of every package under `pkg/engine/controls`, so an area's package needs no block of its own. The controls return data; `pkg/output` and the main menu render it.
12. **Tests**, per area: `hostfake` fixtures for the supported platforms that differ for the area (at least Debian 13, Ubuntu 26.04, Alpine 3.24 and Proxmox VE 9), each state of each control, every `Unknown` path, `Engine.Check` over the area's `Controls()`, `ErrNotMigrated` from `Plan` and `Engine.Plan`'s refusal, every finding's code registered, and no call that changes the fake.
