# Editing hardn.yml in place: the save every slice uses (`config.Edit`)

> **Unit:** refactor plan slice 2 (DNS, the pilot of the full flow), `next/s2-config-edit`, on `next/s2-engine-gallery`. **The maintainer's decision of 2026-10-22, amending plan §3.19 for every slice:** "Change the hardn.yml save to edit only the keys that changed, keeping the rest of the file and its comments, for every slice; drop the comments-lost warning." §3.19 (approved 2026-10-17: save to the loaded path, one atomic save function, warn that comments are lost) keeps its first two points; the third is gone. Builds on [control-dns.md](control-dns.md) §2.9 (the save as a change kind, `steps.PlanSave`, `next/s2-control`) and slice 2's decision 1 ([gallery-dns.md](gallery-dns.md) §4), which the maintainer's amendment is recorded under. V-numbers: none new; side-effects row 29 (`./hardn.yml` saved whole) is the legacy path, untouched.
> **Status:** built and tested on macOS, in process, on the recording fake (`hostfake`) and on bytes. Nothing has run on Linux: the save's write on a host is "written, not run (gate 5)" (§9). Nothing is wired into `cmd/hardn` or the live main menu; the legacy `SaveConfig` and its `./hardn.yml` path are untouched. **Every word new here is proposed** (§5).

## 1. Why

Until this unit `config.Save` wrote `config.Marshal` of the whole configuration: a five-line `hardn.yml` became about fifty keys, every default pinned (`sudoNoPassword: true`, `permitRootLogin: "no"`, `enableBackups: true`, ...), its comments dropped, and the plan warned "Saving hardn.yml loses its comments" (`CONFIG_COMMENTS_LOST`; the gallery's `dns-cloudflare-debian13` showed it). A default written into the file is no longer a default: a later release that changes it would not reach that host. The maintainer chose the edit.

## 2. Guarantees

### The edit (`config.Edit(original []byte, to *Config) ([]byte, error)`)

1. **The settings that changed, alone.** `from` is `original` decoded as the loaders decode it (the defaults, then the file: `DefaultConfig` and `yaml.Unmarshal`, as `config.Read` and `LoadConfig` do). Each setting of `to` is compared with `from`'s by its canonical encoding (`permitRootLogin` as its string, as `canonical` gives it). A setting whose value differs is changed in `original`'s bytes, at its value; **every other byte stays as it was**: key order, blank lines, indentation, quoting, unknown keys, the comments of the file's head, above and beside each key, inside a list and after it. **The one exception is a block list's item that the new list replaces or removes: its lines go, its comments with them** (§2.3, decision 3); the plan's diff shows each line that goes. `TestEdit` pins each case's exact output bytes; `TestEditExample` edits `hardn.yml.example`, commented on nearly every line, and checks the output is the input but for the nameservers' items (one added, one removed, one kept with its line), `sshPort`'s value, and `confirmTimeout` added after the last setting.
2. **A default is never written.** A setting the file does not have differs only when `to`'s value is not its default (what the file, as loaded, gives it); then it is added at the end of its mapping, after the mapping's last value and the comment lines indented past its keys that follow that value (a list's commented-out items), before the other comments that follow it, at its keys' column ("a default is not written", "a key added at the end of the mapping, before the comments after it", "a key added after a list's commented-out items").
3. **Each value in its own form.** A scalar is replaced where it is written, in its own quotes when it is a string (`"alice"` → `"bob"`, `'alice'` → `'bob'`), otherwise as yaml.v3 writes it (plain, or quoted where it must be: `""`; inside braces as yaml.v3 writes a value there, so `bob, george` is quoted), always on one line (a string with a line break, double-quoted); a tag before it goes with it. A list in brackets stays in brackets, on one line, its items quoted as its first was. **A block list is edited item by item**: the items the new list keeps keep their lines, their line comments and the comment lines above them; the new items take the list's dash column, the spaces after it and its first item's quotes; a removed or replaced item's lines go, its comments with it (the longest run of items kept, in order: `script`). The blank and comment lines between the key and the first item are the list's, not an item's: they stay, whatever the items become, so a preset replacing every item keeps a comment written under `nameservers:`. Comment lines after a list's last item (a commented-out entry) stay where they are. A list emptied becomes `[]` on its key's line, the item lines going and the comments after it staying. A list the file has as nothing, `~` or `[]` takes the file's list style: the geometry and quoting of its first block list, or brackets when its only lists are in brackets, or two spaces, a dash and one space (`hardn.yml.example`'s). A mapping is edited at the key that changed, and a key it lacks added at its end (`TestEditNested`). A list's new items that are mappings (`ufwAppProfiles`) are written without the fields whose value is empty, false or 0, which an item read without them has (a default is not written; `{}` for an item with none), and with their lists in the style of the list's first item's lists (in brackets, or its dash geometry).
4. **The text's own forms kept.** CRLF line ends (new lines take the file's first line break), a UTF-8 byte order mark, a leading `---` and a `%YAML` directive, a key quoted, a tab after a colon, characters before a value (columns are counted in characters, as yaml.v3 counts them), a value on the line after its key, a plain or quoted value over several lines, a block scalar (its header's comment kept; its text the lines indented to its text's column, which its indentation indicator gives or else its first line, so a comment after it indented less than its text, which yaml.v3 gives to the next key, stays; a tag before its header goes with it), a last line with no line break (added keys keep it so), a mapping in braces (a key added after its last value, or inside `{}`), a mapping indented as a whole, a file of comments alone, an empty file or a lone `---` (the settings appended at the end, a line break added before them when the file has none). Each is a case of `TestEdit`.
5. **Never corrupt the file: refused, writing nothing** (`EditError`, §5), each case tested:
   - before editing, a file in a form the edit does not take apart (`ErrNotEditable`): more than one YAML document; a document end (`...`); a root that is not a mapping (`~`); a merge (`<<`) into a mapping it edits; a setting to change with an anchor or an alias anywhere in it (its key or value: an edit through an alias would change the other key too; an alias or anchor on an unchanged key is kept); a comment inside a changed list in brackets (collapsed onto one line it would be lost); an explicit key (`? key`), on any setting; a key off its mapping's column otherwise (a tag on the mapping: `--- !!map`); a value whose end the editor cannot find or that it cannot write on one line; line breaks other than LF and CRLF (a lone CR, NEL, LS or PS, which yaml.v3 counts as line breaks and the editor would not); not UTF-8 (a UTF-16 file, which yaml.v3 reads; other bytes that are not UTF-8 yaml.v3 refuses first, `ErrInvalidFile`);
   - **after editing, the edited bytes read back** (`check`, `ErrEditUnsafe`): one document; decoded as the loaders decode them, exactly `to`, every setting compared; and every key of the original but the settings changed, unknown keys and `logsconfig` included, decoded (into `any`) as before, with no key added but those (`TestEditChecks`: a setting not changed, one changed though not to save, an unknown key changed or removed, `logsconfig` changed, a key added, bytes that do not parse, two documents). One edit is refused so (`TestEdit`; with the engine, the DNS control's `TestRefusals`): a key added after a block scalar that ends the file with no line break, which would give that scalar a line break it did not have;
   - bytes that do not decode at all (a key given twice, a tab as indentation): `ErrInvalidFile` (`CONFIG_FILE_INVALID`), as `config.Read` refuses them.
6. **A property** (`TestEditKeepsTheRest`, 300 seeded runs over a file commented throughout, a comment under a list's key among them, random changes to the user name, the port, a quoted string, a bool, two block lists and an added key): the output decodes to the configuration saved, every line outside the items and values changed is kept in order, and each changed scalar keeps its comment. **A fuzz test** (`FuzzEdit`: nine changes over any bytes that decode, the ninth the list saved alone with the user name changed in memory only; its seeds run with the tests): a 60-second run of it on this machine, and a 90-second run of an earlier copy, about 1.9 million inputs in all, found no panic and no saved bytes that read back otherwise; their corpus showed the one refusal of the read-back noted above, and UTF-16 files. After the review fixes, a 90-second run of the nine changes, about 1.8 million inputs, found none either.
7. **`logsconfig` is not a setting** (`derivedKey`): `LoadConfig` sets `LogsConfig.LogFilePath` from `logFile` whatever the file says, and nothing reads it from the file. The edit neither compares nor writes it: a file's `logsconfig` stays as it is (legacy saves wrote one) and none is added for the value `LoadConfig` derived ("logsconfig as LoadConfig sets it, not added"). The read-back requires it to decode as before.
8. **A deprecated value is rewritten only when its value changes** (edit only what changed): `permitRootLogin: false` stays until the value changes, then becomes `"yes"` or `"no"` (§3.17's canonical string), its comment kept.
9. **The settings named alone** (`Edit(original, to, settings...)`, the review fixes): with settings named (their `hardn.yml` keys), only those are compared and written; every other setting stays as the file gives it, whatever `to` holds in memory. `cmd/hardn` sets `cfg.DryRun` from `-n` and `cfg.Username` from `-u` after loading; a save of every setting would write them. With none named, every setting (the tests' and `TestEditExample`'s form). A name that is no setting, `logsconfig` included, is `fs.ErrInvalid` (`TestEditSettings`).

### The save (`config.Save`) and its plan (`steps.PlanSave`)

10. **`config.Save` is built on `Edit`** (`Save(ctx, sys, c, settings...)`, the settings passed on): to the loaded path (`ErrNotLoaded` without one), the file read not through a symlink (`host.ErrSymlink`), refused when its bytes are not the ones the configuration was read from or last saved (`ErrChanged`, `CONFIG_CHANGED`: the edit compares with the file as read, so it would undo an edit made since), `Edit`'s bytes written atomically (`host.WriteFileAtomicKeep`, mode and owner kept), and nothing written when nothing changed (`TestSave`, `TestRead`).
11. **`steps.PlanSave` plans `Edit`'s bytes**, of the settings the calling control names (`PlanSave(ctx, sys, id, cfg, settings, after...)`; none named is `fs.ErrInvalid`, so no control saves every setting by leaving them out): none when the file already gives the configuration's values of them (it returns `[]engine.Change`, empty then); otherwise one change, "Save the configuration", **its diff the edited lines alone**, and **no finding** (`CONFIG_COMMENTS_LOST` removed). An edit `Edit` refuses is a refusal before anything changes, with a report (§5). Its other refusals (`CONFIG_NOT_LOADED`, `SYMLINK_REFUSED`, `CONFIG_CHANGED`), its Apply's checks (the backup as the plan read it; the configuration still giving the bytes shown, else `PLAN_CHANGED`) and its failure ("Saving <path> failed", the changes before it rolled back) are `next/s2-control`'s, unchanged (`TestPlanSave`).
12. **The DNS control's save** (`dns.nameservers/save`, `dns.Setting`: `nameservers` alone) now shows the list's lines alone, whatever else `in.Config` holds in memory (`TestApply` gives it a user name and a dry run that the file does not have, and the file keeps its own): Debian 13's preset on the scenarios' file (`# hardn's configuration (web-01.example.net)`, `username: alice`, `nameservers:` with two items) has the diff `@@ -1,5 +1,5 @@`, the two items replaced, the comment kept; the file is saved byte for byte so (`TestApply`, `TestPlayEngineDNS`).

## 5. Words and codes

All **proposed**. Each refusal is a `steps.Refusal`; `pkg/output` shows the Why with the code, then "To go on: " and the Fix. The Why names the file (and the setting, when one is at issue: for "cannot be edited in place" and `CONFIG_EDIT_UNSAFE`, only a setting the save changes, since those words of another would say the save changes it too; the log keeps the key, `EditError.Error`), the Fix the settings the save changes. *The review fixes reworded three:* the document end (it was "ends its YAML document with ...", which read as a sentence cut short), the explicit key and the value not found (both were "is written in an unusual YAML form", which said nothing to act on); and the sentinel, the registry's line, "hardn.yml cannot be edited in place" (it was "hardn.yml is written in a form that is not edited in place").

| Code | When | Why | Fix |
|---|---|---|---|
| `CONFIG_NOT_EDITABLE` | several documents | `<path>` holds more than one YAML document | set `<settings>` in `<path>` by hand, then try again |
| `CONFIG_NOT_EDITABLE` | a document end | `<path>` has a "..." line | the same |
| `CONFIG_NOT_EDITABLE` | the root not a mapping | `<path>` does not hold its settings as key: value | the same |
| `CONFIG_NOT_EDITABLE` | a merge | `<path>` merges settings with << | the same |
| `CONFIG_NOT_EDITABLE` | an anchor or alias | `<setting> in <path>` uses a YAML anchor or alias | the same |
| `CONFIG_NOT_EDITABLE` | a comment in brackets | `<setting> in <path>` has comments inside its brackets | the same |
| `CONFIG_NOT_EDITABLE` | an explicit key (any key) | `<key> in <path>` uses an explicit key (?) | the same |
| `CONFIG_NOT_EDITABLE` | a key off its column (a tag on the mapping), a value whose end is not found or that cannot be written on one line | `<setting> in <path>` cannot be edited in place; `<path>` cannot be edited in place when the key is not a setting the save changes | the same |

| `CONFIG_NOT_EDITABLE` | not UTF-8 | `<path>` is not UTF-8 text | the same |

For DNS: "/etc/hardn/hardn.yml holds more than one YAML document (CONFIG_NOT_EDITABLE)", "To go on: set nameservers in /etc/hardn/hardn.yml by hand, then try again." Once set by hand, "Configure DNS" applies the list with no save. A `hardn.yml` of `username: |` and `  alice` with no last line break, saved with a preset, is "/etc/hardn/hardn.yml cannot be edited safely (CONFIG_EDIT_UNSAFE)": the user name would gain a line break, and the save does not change it, so it is not named (`TestRefusals`, both).

**Codes** (`pkg/output`'s registry): `CONFIG_NOT_EDITABLE` (`config.ErrNotEditable`) and `CONFIG_EDIT_UNSAFE` (`config.ErrEditUnsafe`) added; `config.ErrChanged`, `config.Save`'s, joins `CONFIG_CHANGED`, `steps.ErrConfigChanged`'s code (no code renamed). **`CONFIG_COMMENTS_LOST` removed**, with `steps.CodeCommentsLost`: it was added by `next/s2-control` and never merged or released, so no released code goes (`docs/reference/output.md` §2.2 says so); the rule that a code never goes once released stands. The save's other words are unchanged: "Save the configuration", "Save the configuration to <path>", "Saving <path> failed", "saved <path>".

## 6. Decisions of this unit

1. **`Edit(original, to, settings...)` decodes `from` itself** (the task proposed `Edit(original, from, to)`): `from` is by definition what the bytes decode to, so no caller can pass one that disagrees. (`settings`: decision 12.)
2. **`logsconfig` is left out** (§2.7): the task named it as a nested key to edit at its leaf, but it is derived, not read; comparing it would write the value `LoadConfig` derived into every file loaded through it. Nested mappings are edited at the leaf all the same (`TestEditNested`, on trees given directly); no setting of `Config` is a mapping.
3. **A replaced list item is a removed one and a new one**: its comments go, since they spoke of the old value; the comment lines above an item belong to it, but those above the first item belong to the list and stay (*the review fixes*: a comment written under `nameservers:` was lost to every preset, which replaces each item; it stays now, even when it spoke of the first item, as a comment about the old list); those after the last item stay. *Alternatives:* keep a replaced item's line comment on the new value; or give the lines above the first item to it again, as before the review fixes.
4. **The file's list style for a list it has as nothing or `[]`** (§2.3): legacy saves write `sshKeys: []` beside block lists, so `[]`'s own brackets say nothing of the file's style. A non-empty list in brackets stays in brackets.
5. **A single leading `---` and a directive are kept, not refused** (the task listed "a document separator or several documents (refuse)"): yamllint's document-start rule asks for `---`, the positions and the read-back work the same, and refusing would leave such a file unsaveable; several documents and `...` are refused. Say if a lone `---` should be refused too.
6. **A comment inside a changed list in brackets is refused, not dropped**: the list would be collapsed onto one line.
7. **The read-back covers every key of the file**, unknown keys and `logsconfig` included, not only `Config`'s.
8. **A deprecated value is not rewritten by an unrelated save** (§2.8): the bool stays until its value changes, and §3.17's warning for it, owed by the slices, stays owed ([sshd-migrate.md](../safety/sshd-migrate.md) §22).
9. **`PlanSave` returns `[]engine.Change`**, none when nothing changed, rather than a change with an empty diff that would say "Save the configuration" of a save that changes nothing. Its one caller, the DNS control, appends it.
10. **`config.Save` reads the file and checks `LoadedFrom` itself**, where it wrote without reading: it needs the bytes to edit, and an edit over another one would undo it.
11. **Removed:** `config.Marshal` (what the old save wrote; nothing else used it), `config.HasComments` and `steps.CodeCommentsLost` (the warning), all added by `next/s2-control`, unreleased. `MarshalYAML` and the legacy `SaveConfig` are unchanged.
12. **The save writes the settings its control names, alone** (the review fixes: `Edit(original, to, settings...)`, `Save(ctx, sys, c, settings...)`, `PlanSave(ctx, sys, id, cfg, settings, after...)`; the DNS control's `dns.Setting`, `nameservers`). `cmd/hardn` sets `cfg.DryRun` from `-n` and `cfg.Username` from `-u` after loading, and plan §3.19 keeps "`dryRun` precedence: explicit flag wins, otherwise config"; a save of every setting that differs from the file would write those into `hardn.yml` beside the list (shown in the diff, not hidden, and the same with the old `Marshal`, but not a change the action asked for). Scoping the save holds whatever configuration a later unit gives the control. *Alternative:* a rule for the units that wire the control (unit (c), the main menu's) that `in.Config` carries no flag's value; it would leave each unit, and each later control's caller, to keep it. `PlanSave` refuses no setting named (`fs.ErrInvalid`), so no control saves every setting by omission; `Edit` and `Save` with none name every setting, as the tests and the example use them. `CONFIG_CHANGED` stands (control-dns.md decision 6).
13. **A new list item that is a mapping is written without its empty, false and 0 fields**, its lists in the style of the first item's lists (the review fixes; it was every field, `title: ""` included, and its lists as two spaces, a dash and one): an item read without them has those values, so writing them would pin a default; the read-back holds it.

## 7. API

```go
package config // pkg/config: edit.go and editor.go new
var ErrNotEditable, ErrEditUnsafe, ErrChanged error
type EditError struct { Key, Why string; Keys []string; Err error } // Unwrap: Err
func Edit(original []byte, to *Config, settings ...string) ([]byte, error) // settings: their keys; none: every setting
func Save(ctx context.Context, sys host.System, c *Config, settings ...string) error
// Save: reads the file (no symlink), ErrChanged for other bytes, writes Edit's bytes, nothing when nothing changed
// removed: func Marshal(c *Config) ([]byte, error); func HasComments(data []byte) bool

package steps // pkg/engine/steps
func PlanSave(ctx context.Context, sys host.System, id string, cfg *config.Config, settings []string, after ...string) ([]engine.Change, error) // was (id, cfg, after...) (engine.Change, error)
// removed: const CodeCommentsLost

package dns // pkg/engine/controls/dns
const Setting = "nameservers" // the setting its save writes

package output // codes: CONFIG_NOT_EDITABLE, CONFIG_EDIT_UNSAFE added; config.ErrChanged under CONFIG_CHANGED; CONFIG_COMMENTS_LOST removed
```

`pkg/config` reaches the host only through the `host.System` it is given (`Read`, `Save`); `Edit` reaches nothing. No depguard rule changed (no new package). `TestPlayTouchesNothing` allows `Edit` beside `Read` and `Save`.

- **The legacy `SaveConfig`** (`./hardn.yml`, the whole file, 15 call sites) is untouched; replacing it is the slices'.
